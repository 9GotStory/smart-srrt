The new module is intentionally small and independently testable; it does **not** expand the already-large `04-browser-app.html`. Future dashboard modules, incident tables and report cards can be split into separate trusted HTML partials with an explicit manifest and tests. `Index.html` is **generated from ordered native `include()` calls**, not copied from One-Click.

`tools/build-apps-script-multifile.mjs` reads its ordered sources from `native-sources.mjs`, not `build-one-click.mjs`. Its `--check` compares exact staged byte content and names without writes. The developer build/check commands no longer call One-Click builders. The future operator-only clasp script allows exactly the new 14-file stage plus the original protected `appsscript.json`; it is **not executed** by this PR.

## Mobile Dashboard component scope

- At viewport width **640 CSS px or smaller**, signed-in Dashboard event rows are presented as stacked accessible read-only **cards**. Original 10-column authorized table remains the semantic action source.
- Each card includes the source row's date, area, event, lifecycle, owner, verification, criteria, risk and attachments. The authorized `allData` provides separate investigation choice/date; no additional RPC and no new computed KPI.
- A card's `ดูรายละเอียดและดำเนินการในตาราง` button expands the existing original table and focuses the matching row, so server-role-gated report/edit/attachment controls remain solely in their original source. **No duplicated AI report button or job creation path**.
- Public/guest Dashboard continues to show only aggregate KPIs and charts. The card renderer returns without creating private rows when `currentUser` is absent; the observer also clears cards on login/logout redraw. The existing aggregate PNG capture and protected raw Excel actions are unchanged.
- The module uses text-only DOM nodes (`textContent`) for event labels and does not embed untrusted HTML, dynamic `onclick` scripts, or remote assets.
- Cards do **not** yet replace the Event Management and AI Reporter mobile tables; those are later separately approved slices. Google Charts remains; this PR does not introduce Chart.js.

### Remaining assurance gaps

- Source/static tests and CI do not substitute for a fully browser-run Apps Script IFRAME UAT, visual responsive review, keyboard/screen-reader testing or performance benchmarking.
- Dashboard mobile cards are a first design increment; do not claim five-screen high-fidelity redesign, full mobile Event/Reporter cards or complete accessibility.
- The current public byVillage aggregate has no small-cell suppression; do not interpret "aggregate only" as proven anonymous.
- The legacy `04-browser-app.html` remains large; its safe decomposition into purpose-specific native modules needs another exact-source/test/RPC contract change rather than a bulk move in this PR.
