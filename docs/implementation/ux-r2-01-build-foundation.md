## What this slice actually changes

- Introduces `tailwindcss@4.3.3` and `@tailwindcss/cli@4.3.3` as **exact devDependencies**, with committed `package-lock.json`; `npm ci --ignore-scripts` in GitHub Actions.
- Moves the byte-identical current CSS inside the old `<style>…</style>` wrapper to `src/styles/legacy.css` (authored source). Original selectors are preserved. This is **not** a visual redesign.
- Introduces `src/styles/tailwind.css` using `prefix(tw)`, **Preflight disabled**, and an explicit three-class source probe (`tw:flex`, `tw:gap-4`, `tw:items-center`). Those classes are **not used by current HTML**; no operational component restyling occurs in R2-01.
- Adds `tools/build-ui-assets.mjs` to compile Tailwind locally and concatenate the current CSS into the original `src/web/01-styles.html` partial. No new Apps Script source file, HTML fragment, external runtime CSS request or application JavaScript dependency is created.
- `npm run build` now regenerates the CSS partial then tracked One-Click artifact. `npm run build:check` verifies CSS **without writing tracked files**, then existing exact One-Click byte parity.
- Updates `Index_Smart_SRRT_OneClick.html` as a derived tracked release artifact, leaving server One-Click bytes unchanged. Native Multi-file staging remains the existing **7 server .gs + 5 HTML fragments + Index.html = 13**.
- Adds synthetic Node tests proving compiled CSS reproducibility, legacy style preservation, drift rejection, and `--check` no-write behavior.
- Removes the **temporary bootstrap workflow** used to generate first pinned artifacts on GitHub Node 24; only the existing `.github/workflows/tests.yml` remains, now with pinned install and asset check.

## Commands for a future approved developer checkout

```bash
npm ci --ignore-scripts --no-audit --no-fund

# Read-only source/generated artifact comparison
npm run check:ui-assets
npm run build:check

# Only when intentionally updating CSS inputs (writes tracked release files):
npm run build

# Staging verification: writes ignored dist/ but never production Apps Script
npm run build:gas-multifile
npm run check:gas-multifile
npm run check:contracts
npm run release:preflight
npm test
```

**Do not run `npm run build` automatically in CI**: that would mask accidentally stale tracked files. CI runs `check:ui-assets` and `build:check` read-only, then the existing isolated staging and test gates.

## Why Preflight and UI migration are deferred

Current `01-styles.html` includes global `*{box-sizing:border-box}`, button/input styling, responsive sidebar, table/form rules and modal overlays. Tailwind v4 Preflight can replace browser defaults, so it is **intentionally not imported** in R2-01. The new CSS is prefixed; visible components keep existing classes until dedicated R2-02 and later PRs.

No `lucide-static` or `chart.js` package is installed in this slice. They are deferred to separate component/chart implementation PRs per the ADR, where runtime iframe, raw-data privacy, Canvas PNG capture and one-action-per-Event behavior need concrete tests.

## Release / risk controls

- No changes to server `.gs`, login/session, permissions, Data Schema, Google Sheet/Drive, report registry, Gemini prompt/job state, or Apps Script script/deployment identifiers.
- No Browser/Figma, live health-data, Apps Script iframe or full production UAT claims in this R2-01 unit/build slice.
- **ChatGPT Technical Review** is the Product Owner-selected review workflow; disclose the author-assisted/non-independent nature and verify the final commit, diff and CI.
- **PR Merge: requires explicit Product Owner authorization.**
- **Production Apps Script deployment @10: untouched**, and always requires separate approval.
- Rollback: restore `src/web/01-styles.html`, One-Click artifact and build scripts from the last approved `main` SHA; do not directly mutate running Apps Script.
