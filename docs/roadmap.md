เสร็จเมื่อ: หน้าเว็บเปล่าเปิดได้จากที่อยู่จริง เรียก API ได้คำตอบ คำขอตรวจรุ่นคืนเลขรุ่นของโค้ดกับโครงสร้าง CI ผ่าน รู้ว่า Apps Script project เดิมเป็นโปรเจกต์แยกหรือผูกกับไฟล์ฐานข้อมูล มีผลวัดเวลาตอบของ API จากมือถือจริงเทียบกับเป้า 3 วินาที และมีผลวัดว่าคำขอพร้อมกันของผู้ที่ไม่ล็อกอินถูกปฏิเสธที่จำนวนเท่าใด และกระทบคำขอของผู้ที่ล็อกอินหรือไม่ ([`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน))

ผลข้างเคียง: ระบบเก่าที่ deploy อยู่หยุดให้บริการ โค้ดและเอกสารของระบบเก่าอยู่ที่ tag `legacy-v1` Apps Script ไม่กู้ version เก่าให้เอง การนำระบบเก่ากลับมาจึงต้องส่งโค้ดจาก tag นั้นขึ้นไปใหม่ และกู้ไฟล์ฐานข้อมูลจากชุดสำรองของช่วงนี้ ([ผลการค้น ข้อ 6.1](research/backup-environment-facts.md))

## ช่วงที่ 1 — เข้าสู่ระบบ ผู้ใช้ และข้อมูลตั้งต้น

- ล็อกอินด้วย Google และตรวจอีเมลกับตาราง `users`
- ผู้ดูแลคนแรกถูกสร้างจากค่าตั้งของ Apps Script
- ผู้ดูแลจัดการผู้ใช้บทบาท `admin` และ `unit`: เพิ่ม แก้ไข ระงับ และเปิดใช้ใหม่
- ผู้ดูแลจัดการหน่วยบริการ หมู่บ้าน รายการโรค และชื่อ โลโก้ กับช่องทางติดต่อของหน่วยงาน รายการโรครวมค่า "แสดงชื่อใน Dashboard สาธารณะ" ของแต่ละโรค
- PO ใส่หน่วยบริการจริงและหน่วยที่รับผิดชอบจริงของทุกหมู่บ้าน เพราะสองอย่างนี้ไม่ถูกล้างเมื่อเริ่มใช้ข้อมูลจริง ([`schema.md` ข้อ 9](schema.md#9-การเริ่มใช้ข้อมูลจริง)) บัญชีผู้ใช้ เหตุการณ์ และผู้ป่วยยังเป็นข้อมูลสมมติ
- PO เปลี่ยนสถานะของหน้ายินยอมของ Google เป็น In production ตามขั้นตอนที่เตรียมให้ ([`spec.md` ข้อ 8](spec.md#ชุดใช้งานจริงและชุดทดสอบ))
- แถบข้อมูลสมมติบนทุกหน้า
- นำหมู่บ้านและประชากรเข้าจากไฟล์สถิติของกรมการปกครอง แล้วผู้ดูแลกำหนดหน่วยที่รับผิดชอบของแต่ละหมู่บ้าน ตาม [`schema.md` ข้อ 4](schema.md#4-ข้อมูลตั้งต้น)
- session 7 วัน ออกจากระบบ ระงับบัญชี และสั่งออกจากระบบทุกเครื่อง

เสร็จเมื่อ: ผู้ใช้ในตารางเข้าได้ตามบทบาท อีเมลนอกตารางและบัญชีที่ระงับถูกปฏิเสธ และ**ลิงก์ที่มี `openExternalBrowser=1` ซึ่งส่งในแชต LINE เปิดในเบราว์เซอร์ของเครื่อง ล็อกอินได้ และกลับมาที่หน้าเดิม บนมือถือจริงทั้ง iPhone และ Android**

เอกสารของ LINE และของ Google ระบุว่าการล็อกอินด้วย Google ใช้ไม่ได้ในเบราว์เซอร์ในแอปของ LINE ([ผลการค้นเรื่องข้อความ LINE](research/line-message-facts.md) ส่วนที่ 3 และ 4) การทดสอบนี้จึงบันทึกด้วยว่าหน้าล็อกอินที่ถูกเปิดในเบราว์เซอร์ในแอปของ LINE บอกวิธีเปิดในเบราว์เซอร์ของเครื่อง ถ้าข้อสุดท้ายไม่ผ่าน ให้หยุดและเสนอทางเลือกต่อ PO ก่อนทำช่วงถัดไป ([ADR-0003](adr/0003-google-sign-in-with-email-allowlist.md))

## ช่วงที่ 2 — เหตุการณ์ของผู้ดูแล

- รับแจ้ง ตรวจสอบข่าว ประเมินเกณฑ์ ปิด และเปิดใหม่
- แจ้งเตือนข่าว แก้ไขข้อมูลเหตุการณ์ แก้ผลการตรวจสอบ และยกเลิก
- กำหนดเริ่มสอบสวน และกำหนดเวลาตามกฎหมายของโรคติดต่ออันตราย
- ผู้ป่วยในเหตุการณ์: ผู้ดูแลเพิ่ม แก้ ยกเลิก และประเมินเกณฑ์ใหม่
- ไทม์ไลน์
- หน้ารายการเหตุการณ์พร้อมตัวกรองและการค้นด้วยเลขที่เหตุการณ์ ตัวกรองหน่วยบริการเพิ่มในช่วงที่ 3
- หน้า "งานวันนี้" กลุ่มรอตรวจสอบ รอประเมินเกณฑ์ เข้าเกณฑ์ ยังไม่ได้มอบหมายงาน ยังไม่ได้แจ้งเตือนข่าว และรอปิด ในช่วงนี้แถวของกลุ่มเข้าเกณฑ์ ยังไม่ได้มอบหมายงาน มีปุ่มเปิดเหตุการณ์แทนปุ่มมอบหมายงาน

เสร็จเมื่อ: ผู้ดูแลเดินเหตุการณ์จากรับแจ้งถึงปิดได้ครบ การแก้ไขพร้อมกันสองหน้าจอถูกปฏิเสธด้วยข้อความที่เข้าใจได้ และการกดซ้ำไม่สร้างรายการซ้ำ

## ช่วงที่ 3 — งานของหน่วยบริการ

- มอบหมายงาน และข้อความ LINE พร้อมลิงก์ ทั้งจากผู้ดูแลและจากหน่วยบริการ
- หน้า "งานของหน่วย" บนมือถือ รับงาน บันทึกผล แนบรูป
- งานของ สสอ. การบันทึกผลแทนหน่วยบริการ การแก้ผล และการยกเลิกงาน
- หน่วยบริการแจ้งเหตุการณ์ และเพิ่มผู้ป่วย
- หน้า "งานวันนี้" ปุ่มมอบหมายงาน และกลุ่มงานของ สสอ. งานที่ยังไม่ได้แจ้งหน่วยบริการ งานเกินกำหนดและใกล้ครบกำหนด ผู้ป่วยรายใหม่จากหน่วยบริการ และผลรอตรวจ
- กฎสิทธิ์การมองเห็นของ `unit` ครบตาม [`schema.md` ข้อ 6](schema.md#6-กฎสิทธิ์การมองเห็น)

เสร็จเมื่อ: หน่วยบริการทำงานที่ได้รับจนจบบนมือถือ หน่วยบริการอื่นเปิดลิงก์เดียวกันแล้วได้คำตอบว่าไม่พบ ข้อความ LINE ไม่มีชื่อผู้ป่วยกับบ้านเลขที่ และ**บนมือถือจริง ปุ่ม "คัดลอก" กับ "เปิด LINE" ใช้ได้ ลิงก์ในข้อความที่ส่งแล้วกดได้ และตัวอย่างลิงก์ที่ LINE แสดงไม่มีข้อมูลของเหตุการณ์**

## ช่วงที่ 4 — ชุดโรคติดต่อนำโดยยุงลาย

- โครงชุดโรค การเลือกชุดโรคของแต่ละโรค และชุดโรคติดต่อนำโดยยุงลาย
- แบบ "มอบหมายงานตามชุดโรค" และรอบการทำงานตามมาตรการ 3-3-1 (3-7-14-21-28) ฉบับ พ.ศ. 2569
- แบบบันทึกผลของชุด รวมช่อง HI และ CI
- ผลการเทียบเป้าเวลาและผลการเทียบเป้าผล และตารางของชุดโรคในหน้าเหตุการณ์
- หน้า "งานวันนี้" กลุ่มผู้ป่วยที่ยังไม่มีงานตามชุดโรค ป้าย "ผลไม่ถึงเป้า" และเงื่อนไขระยะเฝ้าระวัง 28 วันของกลุ่มรอปิด
- หน้าตั้งค่าชุดโรค

เสร็จเมื่อ: เหตุการณ์ไข้เลือดออกได้งานและกำหนดเสร็จตามชุดโรค ผลการเทียบเป้าทั้งสองด้านถูกต้องทั้ง 4 แบบ และมีการทดสอบที่พิสูจน์ว่าเพิ่มชุดโรคสมมติอีกชุดได้โดยไม่แก้ตาราง

ก่อนเริ่มช่วงนี้ ถามเจ้าหน้าที่ของ สสอ. สองเรื่องที่ยังเป็น Not Verified ใน [`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน): ฉบับของมาตรการที่จังหวัดสั่งการ และความเกี่ยวข้องของ D506 กับระบบรายงานที่มาตรการกล่าวถึง

## ช่วงที่ 5 — ผู้ดู สรุป ส่งออก และ Dashboard สาธารณะ

- บทบาท `viewer` การเพิ่มผู้ใช้บทบาทนี้ และหน้า "งานวันนี้" กับหน้ารายการเหตุการณ์แบบอ่านอย่างเดียว
- หน้าสรุปภาพรวม: กติกาการนับ ตัวเลขตามโรค เดือน และพื้นที่ อัตราป่วย งานตามหน่วยบริการ ตัวชี้วัดของมาตรฐานทีม และร้อยละที่ถึงเป้าของชุดโรครายสัปดาห์ระบาด
- ส่งออก Excel สามไฟล์: ตัวเลขสรุป ข้อมูลเต็ม และแบบติดตามมาตรการ 3-3-1 พร้อมตัวเลือกรวมชื่อและบ้านเลขที่
- Dashboard สาธารณะ: ตัวเลขรวมสาธารณะที่คำนวณทุกเช้าวันจันทร์ การซ่อนค่าน้อย ยอดรวมเป็นช่วง โรคที่ไม่แสดงชื่อ ค่าเปิดปิดในหน้าตั้งค่า และลิงก์จากหน้าล็อกอินกับเมนู
- การนำประชากรของปีใหม่เข้า

เสร็จเมื่อ: ทุกคำขอแก้ไขและคำขอส่งออกข้อมูลเต็มจากผู้ดูถูกปฏิเสธที่ server ตัวเลขของหน้าสรุปตรงกับค่าที่นับไว้ล่วงหน้าของชุดข้อมูลสมมติ เลขสัปดาห์ระบาดตรงกับปฏิทินปี 2569 ของกองระบาดวิทยา ไฟล์ที่ไม่ได้เลือกรวมชื่อไม่มีชื่อและบ้านเลขที่ คำตอบของ Dashboard สาธารณะมีเฉพาะตารางรายโรค ตำบล และเดือนที่ไม่มีจำนวน 1 ถึง 4 และไม่มียอดรวมที่คำนวณจากจำนวนจริง โรคติดต่ออันตรายและโรคที่ไม่แสดงชื่ออยู่ในแถว "โรคอื่น ๆ" และเมื่อปิด Dashboard สาธารณะ server ไม่ส่งตัวเลข

ก่อนเริ่มช่วงนี้ ตรวจสามเรื่องที่ยังเป็น Not Verified ใน [`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน): ถามเจ้าหน้าที่ของ สสอ. ว่ามีหน่วยงานใดขอข้อมูลความทันเวลาของมาตรการ 3-3-1 หรือไม่ ตรวจว่ากองระบาดวิทยาเผยแพร่ปฏิทินสัปดาห์ระบาดของปี 2570 แล้วหรือยัง และใช้ผลวัดของช่วงที่ 0 ตัดสินว่าต้องวางสำเนาของตัวเลขรวมสาธารณะไว้ที่ Cloudflare หรือไม่

## ช่วงที่ 6 — ร่างรายงานสอบสวน

PO ย้ายฟีเจอร์นี้จากรุ่นถัดไปเข้ารุ่นแรกเมื่อ 18 พฤศจิกายน 2026 ([ADR-0009](adr/0009-ai-drafts-the-investigation-report.md))

- หน้าร่างรายงานสอบสวน: ข้อมูลที่ระบบมีตามหกหัวข้อ บันทึกการสอบสวน และสิทธิ์ของผู้ดูแล ผู้ดู กับหน่วยบริการ
- แม่แบบ Word แบบบันทึกข้อความ และการสร้างไฟล์ตั้งต้นในเบราว์เซอร์โดยไม่ใช้ AI
- การประกอบข้อความที่ส่งให้ AI: คำแทนของชื่อสถานที่และหน่วยงาน ช่วงอายุ การตรวจชื่อผู้ป่วย และหน้าตรวจก่อนส่ง
- การเรียก Gemini การเก็บร่างล่าสุด การตรวจตัวเลข และการเน้นสีข้อความของ AI ในไฟล์
- การบันทึกเวลาที่เขียนรายงานสอบสวนเบื้องต้นหลังดาวน์โหลด
- ค่าเปิดปิดในหน้าตั้งค่า แถวในไทม์ไลน์ และแถวในบันทึกความปลอดภัย

สองข้อแรกไม่เรียก Gemini และทำก่อน ผู้ดูแลจึงได้ไฟล์ตั้งต้นแม้ PO ยังไม่อนุมัติการเรียก Gemini

เสร็จเมื่อ: ผู้ดูแลดาวน์โหลดไฟล์ตั้งต้นและไฟล์ที่มีข้อความของ AI ของเหตุการณ์สมมติได้ ไฟล์มีหกหัวข้อ ตัวเลขและตารางตรงกับหน้าเหตุการณ์ และไม่มีชื่อผู้ป่วยกับบ้านเลขที่ การทดสอบอัตโนมัติซึ่งใช้คำตอบจำลองพิสูจน์ว่า ข้อความที่ส่งไม่มีชื่อ บ้านเลขที่ อายุเป็นปี และชื่อสถานที่ คำขอถูกปฏิเสธเมื่อข้อความอิสระมีชื่อผู้ป่วย ย่อหน้าที่มีตัวเลขนอกข้อความที่ส่งถูกทำเครื่องหมาย คำขอของหน่วยบริการได้คำตอบว่าไม่พบ คำขอร่าง คำขอแก้ และคำขอข้อมูลสำหรับสร้างไฟล์จากผู้ดูถูกปฏิเสธ และเมื่อปิดการร่างด้วย AI server ไม่เรียก Gemini บนระบบที่ deploy การร่างด้วย Gemini จริงกับข้อมูลสมมติสำเร็จ และ**ไฟล์ที่ PO เปิดใน Word บนเครื่องของ สสอ. แสดงแบบอักษรกับการจัดหน้าถูกต้อง และแก้ต่อได้**

ก่อนเริ่มช่วงนี้ PO ทำสามเรื่องใน [`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน): บอกรูปแบบรายงานที่ สสอ. ใช้จริงและให้แม่แบบ Word ถ้ามี อนุมัติการเรียก Gemini ด้วยข้อมูลสมมติแล้วตั้งกุญแจของ API ตามขั้นตอนที่เตรียมให้ ([ADR-0008](adr/0008-delivery-process-and-gates.md)) และเลือกรุ่นของ Gemini จากผลเปรียบเทียบกับข้อมูลสมมติ

## ช่วงที่ 7 — ทดลองใช้ และเริ่มใช้ข้อมูลจริง

ขั้นตอนของคนในช่วงนี้อยู่ใน [`operations.md`](operations.md) สิ่งที่ระบบทำอยู่ใน [`spec.md` ข้อ 8](spec.md#สำรองข้อมูล)

1. สร้างการสำรองตามรอบ การตรวจชุดสำรอง แถบเตือนของชุดสำรองกับพื้นที่ การตรวจการแชร์ โหมดปิดปรับปรุง และขั้นตอนกู้คืน แล้วรอให้การสำรองตามรอบสำเร็จอย่างน้อยหนึ่งรอบ
2. ทดสอบเส้นทางเต็มตาม[เกณฑ์ยอมรับของรุ่นแรก](spec.md#10-เกณฑ์ยอมรับของรุ่นแรก): Claude Code ด้วย Playwright และ PO บนมือถือจริงทั้ง iPhone และ Android
3. สร้างหน้าคู่มือของหน่วยบริการ หน้าคู่มือของผู้ดูแล และหน้าการคุ้มครองข้อมูลส่วนบุคคล แล้วให้หน่วยบริการ 2 แห่งกับผู้ดูแลคนที่สองทดลองใช้ด้วยข้อมูลสมมติตามโจทย์ และแก้ตามผล
4. PO ยืนยันว่าการทดลองใช้ผ่านตาม[เกณฑ์ผ่าน](operations.md#เกณฑ์ผ่าน)
5. PO ถามสำนักงานสาธารณสุขจังหวัดหกข้อ ([`operations.md` ข้อ 13](operations.md#13-คำถามถึงสำนักงานสาธารณสุขจังหวัด)) ข้อนี้เริ่มได้ตั้งแต่ต้นช่วง และไม่ต้องรอข้ออื่น
6. สร้างชุดทดสอบจากชุดสำรองล่าสุดด้วยขั้นตอนกู้คืน บน Apps Script project โปรเจกต์ Cloudflare Pages และ OAuth client ของตัวเอง งานนี้เป็นการทดลองกู้คืน จากนั้นให้ `main` deploy ขึ้นชุดทดสอบ และให้ชุดแรกตาม branch `release`
7. ซ้อมคำสั่งเริ่มใช้ข้อมูลจริงในชุดทดสอบ แล้วกู้คืนชุดทดสอบจากชุดสำรองอีกครั้ง
8. PO ตั้งบัญชีสำรองกับสคริปต์คัดลอก ทำรายการตรวจของบัญชีเจ้าของ และตรวจว่าโฟลเดอร์ของระบบไม่ได้ถูกแชร์ให้ใครนอกจากบัญชีสำรอง ตามขั้นตอนที่เตรียมให้
9. Claude Code ทำรายงานความพร้อมตาม[รายการตรวจ](operations.md#6-รายการตรวจก่อนเริ่มใช้ข้อมูลจริง) และเปิด PR ที่บันทึกวันเริ่มใช้ข้อมูลจริงที่หัวเอกสารนี้
10. **PO อนุมัติการเริ่มใช้ข้อมูลจริงด้วยการสั่ง merge PR นั้น** แล้ว Claude Code รันคำสั่งเริ่มใช้ข้อมูลจริงในชุดแรกหนึ่งครั้ง ตรวจว่าระบบว่าง ไม่มีแถบข้อมูลสมมติ Dashboard สาธารณะปิด และหน้าร่างรายงานไม่มีปุ่มให้ AI ช่วยร่าง แล้วเลิกเข้าถึงชุดนั้น

เสร็จเมื่อ: เกณฑ์ยอมรับทั้ง 11 ข้อผ่าน ชุดทดสอบที่สร้างจากชุดสำรองเปิดใช้ได้โดยจำนวนแถวของทุกแท็บตรงกับตอนสำรอง และมีเวลาที่ใช้ในการกู้คืนบันทึกไว้ สคริปต์คัดลอกของบัญชีสำรองทำงานสำเร็จหนึ่งรอบ ชุดใช้งานจริงว่าง มีผู้ดูแลคนแรก ไม่มีแถบข้อมูลสมมติ และคำขอตรวจรุ่นของชุดใช้งานจริงคืนเลขรุ่นที่ตรงกับ `release`

ก่อนเริ่มช่วงนี้ ตัดสินวิธีส่งโค้ด API ขึ้น Apps Script ของชุดใช้งานจริง และวัดพฤติกรรมของ Google ที่ยังเป็น Not Verified ใน [`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน) เมื่อสร้างการสำรองในข้อ 1

หลังข้อ 10 Claude Code ทำงานในชุดทดสอบเท่านั้น ทุก Deploy ขึ้นชุดใช้งานจริงคือ PR จาก `main` เข้า `release` ที่ PO สั่ง merge และ PO เปิด Dashboard สาธารณะของชุดใช้งานจริงเองหลังได้คำตอบเรื่องมาตรา 10 ของพระราชบัญญัติโรคติดต่อ พ.ศ. 2558 ([`spec.md` ข้อ 7](spec.md#ความเสี่ยงที่ยอมรับ-และข้อที่ยังไม่ยืนยัน)) PO อนุมัติการเปิดการร่างรายงานด้วย AI ของชุดใช้งานจริงแยกต่างหาก หลังตั้งกุญแจของ Gemini ระดับชำระเงิน ([`spec.md` ข้อ 4](spec.md#ร่างรายงานสอบสวน)) งานประจำปีหลังเริ่มใช้อยู่ใน [`operations.md` ข้อ 12](operations.md#12-งานประจำปี)
