## ช่วงที่ 0 — วางโครง

| งาน | ผู้ทำ |
|---|---|
| ปิด Issue ที่เปิดค้างของระบบเก่าทั้งหมด พร้อมลิงก์มาที่เอกสารชุดนี้ | Claude Code หลัง PR #276 merge |
| กำหนดโครงโค้ดด้วย `codebase-design`: ตรรกะของระบบแยกจากบริการของ Google เพื่อทดสอบในเครื่องได้ และมีคำนิยามของ action ชุดเดียวที่หน้าเว็บกับ server ใช้ร่วมกัน | Claude Code เสนอ PO อนุมัติ |
| วางโครง `backend/` (Apps Script) และ `frontend/` (React) พร้อมการทดสอบและ CI | Claude Code |
| สร้าง OAuth client ใน Google Cloud และเชื่อม repository กับ Cloudflare Pages | PO ตามขั้นตอนที่เตรียมให้ |
| คัดลอกไฟล์ Sheet เป็นชุดสำรอง ตรวจว่าครบ แล้วลบแท็บเก่าและสร้างแท็บตาม [`schema.md`](schema.md) ทำเป็นขั้นสุดท้ายของช่วงนี้ ติดกับการ deploy API ของ v2 ครั้งแรก เพื่อไม่ให้ระบบเก่าค้างอยู่บนฐานข้อมูลที่ถูกล้างแล้ว | Claude Code หลัง PO ยืนยันอีกครั้งก่อนลบ |

เสร็จเมื่อ: หน้าเว็บเปล่าเปิดได้จากที่อยู่จริง เรียก API ได้คำตอบ CI ผ่าน และมีผลวัดเวลาตอบของ API จากมือถือจริงเทียบกับเป้า 3 วินาที

ผลข้างเคียง: ระบบเก่าที่ deploy อยู่หยุดให้บริการ และกู้คืนได้จากประวัติเวอร์ชันของ Apps Script กับ tag `legacy-v1` ซึ่งเก็บโค้ดและเอกสารของระบบเก่าที่ลบออกจาก `main` ใน PR #276

## ช่วงที่ 1 — เข้าสู่ระบบ ผู้ใช้ และข้อมูลตั้งต้น

- ล็อกอินด้วย Google และตรวจอีเมลกับตาราง `users`
- ผู้ดูแลคนแรกถูกสร้างจากค่าตั้งของ Apps Script
- ผู้ดูแลจัดการผู้ใช้บทบาท `admin` และ `unit`: เพิ่ม แก้ไข ระงับ และเปิดใช้ใหม่
- ผู้ดูแลจัดการหน่วยบริการ หมู่บ้าน รายการโรค และชื่อกับโลโก้หน่วยงาน
- นำหมู่บ้านและประชากรเข้าจากไฟล์สถิติของกรมการปกครอง แล้วผู้ดูแลกำหนดหน่วยที่รับผิดชอบของแต่ละหมู่บ้าน ตาม [`schema.md` ข้อ 4](schema.md#4-ข้อมูลตั้งต้น)
- session 7 วัน ออกจากระบบ ระงับบัญชี และสั่งออกจากระบบทุกเครื่อง

เสร็จเมื่อ: ผู้ใช้ในตารางเข้าได้ตามบทบาท อีเมลนอกตารางและบัญชีที่ระงับถูกปฏิเสธ และ**เปิดลิงก์จาก LINE บนมือถือจริงแล้วล็อกอินได้**

ถ้าข้อสุดท้ายไม่ผ่าน ให้หยุดและเสนอทางเลือกต่อ PO ก่อนทำช่วงถัดไป ([ADR-0003](adr/0003-google-sign-in-with-email-allowlist.md))

## ช่วงที่ 2 — เหตุการณ์ของผู้ดูแล

- รับแจ้ง ตรวจสอบข่าว ประเมินเกณฑ์ ปิด และเปิดใหม่
- แจ้งเตือนข่าว แก้ไขข้อมูลเหตุการณ์ แก้ผลการตรวจสอบ และยกเลิก
- กำหนดเริ่มสอบสวน และกำหนดเวลาตามกฎหมายของโรคติดต่ออันตราย
- ผู้ป่วยในเหตุการณ์: ผู้ดูแลเพิ่ม แก้ ยกเลิก และประเมินเกณฑ์ใหม่
- ไทม์ไลน์
- หน้า "งานวันนี้" รายการที่ 1, 2, 6 และ 7

เสร็จเมื่อ: ผู้ดูแลเดินเหตุการณ์จากรับแจ้งถึงปิดได้ครบ การแก้ไขพร้อมกันสองหน้าจอถูกปฏิเสธด้วยข้อความที่เข้าใจได้ และการกดซ้ำไม่สร้างรายการซ้ำ

## ช่วงที่ 3 — งานของหน่วยบริการ

- มอบหมายงาน และข้อความ LINE พร้อมลิงก์ ทั้งจากผู้ดูแลและจากหน่วยบริการ
- หน้า "งานของหน่วย" บนมือถือ รับงาน บันทึกผล แนบรูป
- หน่วยบริการแจ้งเหตุการณ์ และเพิ่มผู้ป่วย
- หน้า "งานวันนี้" รายการที่ 3, 4 และ 5
- กฎสิทธิ์การมองเห็นของ `unit` ครบตาม [`schema.md` ข้อ 6](schema.md#6-กฎสิทธิ์การมองเห็น)

เสร็จเมื่อ: หน่วยบริการทำงานที่ได้รับจนจบบนมือถือ หน่วยบริการอื่นเปิดลิงก์เดียวกันแล้วได้คำตอบว่าไม่พบ ข้อความ LINE ไม่มีชื่อผู้ป่วยกับบ้านเลขที่ และ**ปุ่ม "เปิด LINE" ใช้ได้บนมือถือจริง**

## ช่วงที่ 4 — ชุดไข้เลือดออก

- โครงชุดโรค และชุดไข้เลือดออก
- รอบการทำงานตามมาตรการ 3-3-1-7-14-21-28 และผลการเทียบเป้า
- แบบบันทึกผล HI/CI
- หน้าตั้งค่าชุดโรค

เสร็จเมื่อ: เหตุการณ์ไข้เลือดออกได้งานและกำหนดเสร็จตามชุดโรค ผลเทียบเป้าถูกต้องทั้ง 4 แบบ และมีการทดสอบที่พิสูจน์ว่าเพิ่มชุดโรคสมมติอีกชุดได้โดยไม่แก้ตาราง

## ช่วงที่ 5 — ผู้ดู สรุป ส่งออก และ Dashboard สาธารณะ

- บทบาท `viewer` และการเพิ่มผู้ใช้บทบาทนี้
- หน้าสรุปภาพรวม
- ส่งออก Excel
- Dashboard สาธารณะพร้อมการซ่อนค่าต่ำกว่า 5
- การนำประชากรของปีใหม่เข้า

เสร็จเมื่อ: ทุกคำขอแก้ไขจากผู้ดูถูกปฏิเสธที่ server และ Dashboard สาธารณะคำนวณย้อนหาช่องที่ซ่อนไม่ได้

## ช่วงที่ 6 — ทดลองใช้ และเริ่มใช้จริง

1. สำรองข้อมูลอัตโนมัติทุกสัปดาห์ และทดลองกู้คืนจากชุดสำรองหนึ่งครั้ง
2. ทดสอบเส้นทางเต็มตาม[เกณฑ์ยอมรับของรุ่นแรก](spec.md#10-เกณฑ์ยอมรับของรุ่นแรก)
3. เตรียมคู่มือสั้นสำหรับผู้ใช้หน่วยบริการ แล้วให้หน่วยบริการ 1–2 แห่งทดลองใช้ด้วยข้อมูลสมมติ และแก้ตามผล
4. PO ยืนยันว่าผ่าน
5. PO กำหนดระยะเวลาเก็บข้อมูล
6. คัดลอกโครงสร้างและข้อมูลสมมติออกเป็นชุดทดสอบและพัฒนา
7. PO เพิ่มบัญชี Google สำรองให้เข้าถึงโฟลเดอร์ของระบบ เปิดการยืนยันตัวตนสองชั้นของบัญชีเจ้าของ และตรวจว่าไฟล์ฐานข้อมูลกับโฟลเดอร์รูปถ่ายไม่ได้ถูกแชร์ออกไป
8. ล้างข้อมูลสมมติในชุดแรก
9. **PO อนุมัติการเริ่มใช้ข้อมูลจริง**

หลังข้อ 9 Claude Code ทำงานในชุดทดสอบเท่านั้น และทุก Deploy ขึ้นชุดใช้งานจริงต้องขออนุมัติแยก
