> สถานะ: เขียนเมื่อ 17 พฤศจิกายน 2026 จากข้อยุติของฟีเจอร์ที่ 11 ยังไม่มีโค้ดของ v2 ใน repository คำสั่งจริงของแต่ละขั้นถูกเติมในช่วงที่ 7 ของ [roadmap](roadmap.md) เมื่อมีโค้ดแล้ว
> เอกสารนี้บอกว่า**คน**ทำอะไร เมื่อไร และตรวจอะไร สิ่งที่**ระบบ**ทำอยู่ใน [`spec.md` ข้อ 8](spec.md#8-ข้อกำหนดทั่วไป) เมื่อสองไฟล์เขียนไม่ตรงกัน spec เป็นแหล่งอ้างอิง ข้อเท็จจริงของ Google และ Cloudflare อยู่ใน[ผลการค้นเรื่องการสำรองและการแยกชุด](research/backup-environment-facts.md) ข้อเท็จจริงของกฎหมายอยู่ใน[ผลการค้นเรื่องอายุการเก็บและหน้าที่ตามกฎหมาย](research/data-retention-governance-facts.md)

## 1. ใครทำอะไร

| งาน | ก่อนเริ่มใช้ข้อมูลจริง | หลังเริ่มใช้ข้อมูลจริง |
|---|---|---|
| ดูแถบเตือนของชุดสำรอง พื้นที่ และการแชร์ | ผู้ดูแล | ผู้ดูแล |
| Deploy | การอนุมัติ Merge เข้า `main` ครอบคลุม | PO สั่ง merge PR จาก `main` เข้า `release` ทุกครั้ง (ข้อ 8) |
| กู้คืน | Claude Code หลัง PO อนุมัติ | PO ทำเองในชุดใช้งานจริง Claude Code ทำในชุดทดสอบ |

| แจ้งเหตุละเมิดข้อมูลส่วนบุคคล | ไม่มีข้อมูลจริง | PO หรือผู้ที่ผู้ควบคุมข้อมูลกำหนด (ข้อ 10) |

## 2. ชุดสำรอง

ระบบสำรองเองทุกคืนวันอาทิตย์ ([spec ข้อ 8](spec.md#สำรองข้อมูล)) คนมีงานเมื่อแถบเตือนขึ้นเท่านั้น

1. เปิดหน้าตั้งค่า ดูเวลาของชุดสำรองล่าสุดและพื้นที่ที่ใช้
2. ถ้าพื้นที่ใช้เกินร้อยละ 80 เจ้าของบัญชีลบไฟล์ส่วนตัวที่ไม่เกี่ยวกับระบบ ล้างถังขยะของ Drive หรือซื้อพื้นที่เพิ่ม เจ้าของบัญชีไม่ลบไฟล์ในโฟลเดอร์ของระบบ
3. ถ้าพื้นที่ไม่ใช่สาเหตุ เจ้าของบัญชีเปิดหน้า Executions ของ Apps Script และอีเมล "Summary of failures" ของ Google แล้วส่งข้อความของข้อผิดพลาดให้ Claude Code ข้อความนั้นไม่มีข้อมูลผู้ป่วยตามกฎข้อ 8 ของ `CLAUDE.md`
4. สาเหตุที่เอกสารของ Google ระบุไว้ คืองานตามเวลาขออนุญาตจากเจ้าของบัญชีเองไม่ได้ เมื่อโค้ดรุ่นใหม่ใช้บริการของ Google เพิ่ม เจ้าของบัญชีต้องเปิด Apps Script แล้วกดอนุญาตหนึ่งครั้ง ขั้นนี้อยู่ในรายการของทุก Deploy ที่เพิ่มบริการ

งานตามเวลาเป็นของบัญชีที่สร้าง และคนอื่นมองไม่เห็น งานตามเวลาของระบบจึงสร้างด้วยฟังก์ชันติดตั้งในโค้ด ไม่สร้างด้วยมือ และแต่ละชุดมีงานตามเวลาของตัวเอง

## 3. กู้คืน

ใช้เมื่อไฟล์ฐานข้อมูลเสียหาย ถูกลบ หรือมีข้อมูลผิดจำนวนมากที่แก้ทีละรายการไม่ได้ ความผิดพลาดที่พบภายในไม่กี่ชั่วโมงให้ดูประวัติเวอร์ชันของ Google Sheets ก่อน เพราะเสียข้อมูลน้อยกว่า

1. ตัดสินว่าจะใช้ชุดสำรองชุดใด และยอมเสียข้อมูลตั้งแต่เวลาของชุดนั้น
2. เปิดโหมดปิดปรับปรุง
3. คัดลอกชุดสำรองที่เลือกเป็นไฟล์ใหม่ในโฟลเดอร์ของระบบ ไม่แก้ชุดสำรองต้นทาง
4. เปลี่ยน ID ของไฟล์ฐานข้อมูลใน Script Properties ให้ชี้ไฟล์ใหม่
5. รันฟังก์ชันตรวจ ซึ่งเทียบเลขรุ่นของโครงสร้างและจำนวนแถวของทุกแท็บกับชุดสำรอง นับรูปที่ไม่มีแถวอ้างถึง และเพิ่มแถว `database_restored` ในบันทึกความปลอดภัย
6. ปิดโหมดปิดปรับปรุง แล้วเปิดระบบด้วยบัญชีผู้ดูแลหนึ่งครั้ง
7. แจ้งผู้ใช้ว่าข้อมูลช่วงใดหาย และต้องบันทึกใหม่ ไฟล์เดิมเก็บไว้จนรู้สาเหตุ

ผ่านเมื่อ: ระบบเปิดใช้ได้ จำนวนแถวของทุกแท็บตรงกับชุดสำรอง และรายงานระบุเวลาที่ใช้กับช่วงเวลาของข้อมูลที่หาย

## 4. การทดสอบเส้นทางเต็ม

ทำบนระบบที่ deploy ก่อนเชิญหน่วยบริการทดลองใช้

| ผู้ทำ | สิ่งที่ทำ |
|---|---|
| Claude Code ด้วย Playwright | [เกณฑ์ยอมรับ](spec.md#10-เกณฑ์ยอมรับของรุ่นแรก)ข้อ 1–9 และ "เสร็จเมื่อ" ของช่วงที่ 1–6 ใน roadmap ซ้ำทุกข้อ |
| PO บนมือถือจริง ทั้ง iPhone และ Android | เปิดลิงก์จากแชต LINE ล็อกอิน กลับมาที่หน้าเดิม ถ่ายรูปแล้วแนบกับผล และปุ่ม "คัดลอก" กับ "เปิด LINE" |
| PO บนเครื่องคอมพิวเตอร์ของ สสอ. | เปิดไฟล์รายงานสอบสวนใน Word ตรวจแบบอักษรกับการจัดหน้า และแก้ข้อความได้ |

รายงานแยกหลักฐานสามระดับตาม `CLAUDE.md` ข้อ 7 ข้อที่ทำบนมือถือจริงไม่ได้เขียนว่า **Not Verified**

## 5. ทดลองใช้

### ผู้ทดลอง

- หน่วยบริการ 2 แห่งที่ต่างกัน: แห่งหนึ่งเจ้าหน้าที่คล่องมือถือ อีกแห่งไม่คล่อง ถ้าทำได้ แห่งหนึ่งใช้ iPhone และอีกแห่งใช้ Android PO เป็นผู้เลือก
- ผู้ดูแลคนที่สองของ สสอ. ทดลองในบทบาทผู้ดูแล
- ผู้ทดลองใช้อีเมล Google ส่วนตัวของตนเอง
- เอกสาร Issue และ PR เรียกสองหน่วยนี้ว่า "หน่วยทดลอง ก" และ "หน่วยทดลอง ข" และไม่มีชื่อคน

### โจทย์

ผู้ทดลองทำตามโจทย์ที่เตรียมไว้เท่านั้น เพื่อไม่ให้ข้อมูลจริงเข้าระบบก่อนการอนุมัติ

- ชื่อผู้ป่วยในโจทย์เห็นได้ชัดว่าสมมติ เช่น "นายสมมติ ทดลองหนึ่ง" และบ้านเลขที่ 999/1
- รูปที่แนบเป็นรูปสิ่งของในสำนักงาน ไม่ถ่ายคน บ้าน หรือเอกสาร
- ผู้ทดลองไม่ต้องลงพื้นที่
- ถ้าพบข้อมูลจริง ผู้ดูแลยกเลิกรายการนั้นทันที ข้อมูลของการทดลองทั้งหมดถูกล้างเมื่อเริ่มใช้ข้อมูลจริง

### สองขั้น รวมประมาณหนึ่งสัปดาห์

1. **นั่งดู ครั้งละประมาณ 30 นาทีต่อหน่วย** PO ส่งข้อความ LINE ที่ระบบเตรียมถึงผู้ทดลอง ผู้ทดลองใช้มือถือของตนเองกับคู่มือเท่านั้น ทำสามอย่าง: เปิดลิงก์แล้วล็อกอิน รับงานแล้วบันทึกผลพร้อมรูป และแจ้งเหตุการณ์หนึ่งเรื่อง PO จดจุดที่ติด และช่วยเมื่อไปต่อไม่ได้เท่านั้น
2. **ใช้เอง 7 วัน** PO สร้างเหตุการณ์ไข้เลือดออกสมมติ 2 เรื่องต่อหน่วย กรอกเวลารับแจ้งย้อนหลังให้งานรอบวันที่ 0, 1, 3 และ 7 ครบกำหนดภายในสัปดาห์นั้น ผู้ทดลองรับงานและบันทึกผลเอง

ในขั้นใช้เอง ผู้ดูแลคนที่สองทำเพิ่มหนึ่งอย่าง: มอบหมายงานสอบสวนโรคให้ สสอ. ในเหตุการณ์สมมติหนึ่งเรื่อง บันทึกผลของงานนั้น แล้วร่างรายงานสอบสวนของเหตุการณ์นั้น ทั้งไฟล์ตั้งต้นและไฟล์ที่ AI ช่วยร่าง แล้วเปิดแก้ใน Word บนเครื่องของ สสอ. ([spec ข้อ 4](spec.md#ร่างรายงานสอบสวน))

### คำถามหลังทดลอง

1. ติดตรงไหน
2. ข้อความ LINE เข้าใจหรือไม่ว่าต้องทำอะไร
3. ช่องใดกรอกยาก หรือไม่รู้ว่าจะกรอกอะไร
4. การกรอก HI และ CI ซ้ำกับแอปสมาร์ท อสม. รับได้หรือไม่ คำตอบข้อนี้ใช้ทบทวนข้อเสนอใน [spec ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน)
5. ถามผู้ดูแลคนที่สองเท่านั้น: ไฟล์รายงานสอบสวนที่ได้ ใช้เขียนต่อได้หรือไม่ และต้องแก้ส่วนใดมากที่สุด

### เกณฑ์ผ่าน

PO ยืนยันว่าผ่านเมื่อครบสามข้อ

1. ผู้ทดลองของทั้งสองหน่วยทำสามอย่างของขั้นนั่งดูจบบนมือถือของตนเองโดยไม่มีคนช่วย หน่วยที่ต้องช่วยในรอบแรกทำซ้ำหลังแก้ปัญหาแล้ว
2. ไม่มีปัญหาระดับ "ขวาง" ค้างอยู่ ปัญหาระดับนี้คือ ทำงานไม่จบ ข้อมูลหายหรือผิด เห็นข้อมูลของหน่วยอื่น หรือล็อกอินไม่ได้ ปัญหาระดับอื่นบันทึกไว้ทำหลังเริ่มใช้
3. มีคำตอบของคำถามข้อ 1 ถึง 4 จากทั้งสองหน่วย และคำตอบของข้อ 5 จากผู้ดูแลคนที่สอง

ผลบันทึกเป็น GitHub Issue หนึ่งเรื่องต่อปัญหา ระบบไม่มีแบบสอบถามในตัว

## 6. รายการตรวจก่อนเริ่มใช้ข้อมูลจริง

Claude Code ทำรายงานความพร้อมจากรายการนี้ แยกหลักฐานสามระดับ ข้อที่ PO ทำเองมีขั้นตอนให้ทำตามซึ่งเตรียมในช่วงที่ 7

| ข้อ | ผู้ทำ |
|---|---|
| การสำรองตามรอบสำเร็จอย่างน้อยหนึ่งรอบ และหน้าตั้งค่าแสดงเวลาของรอบนั้น | Claude Code ตรวจ |
| การทดสอบเส้นทางเต็มผ่าน (ข้อ 4) | Claude Code และ PO |
| การทดลองใช้ผ่านตามเกณฑ์ (ข้อ 5) | PO |
| การซ้อมคำสั่งเริ่มใช้ข้อมูลจริงในชุดทดสอบปิดการร่างรายงานด้วย AI ลบกุญแจของ Gemini API และล้างร่างรายงานสอบสวน | Claude Code |
| ชุดทดสอบถูกสร้างจากชุดสำรอง เปิดใช้ได้ และจำนวนแถวตรง (ข้อ 3) | Claude Code |
| คำสั่งเริ่มใช้ข้อมูลจริงถูกซ้อมในชุดทดสอบ แล้วชุดทดสอบถูกกู้คืนจากชุดสำรองอีกครั้ง | Claude Code |
| `main` deploy ขึ้นชุดทดสอบ และ `release` deploy ขึ้นชุดแรก | Claude Code และ PO |
| มีผู้ดูแลที่ใช้งานอยู่อย่างน้อย 2 บัญชี | PO |
| รายการหน่วยบริการและหน่วยที่รับผิดชอบของทุกหมู่บ้านเป็นของจริง | PO |
| ชื่อ โลโก้ และช่องทางติดต่อของหน่วยงานถูกต้อง | PO |
| บัญชีเจ้าของ: เปิดการยืนยันตัวตนสองชั้น ตั้งเบอร์โทรและอีเมลกู้คืน เก็บรหัสสำรองไว้ที่สำนักงาน และมีพื้นที่ว่างไม่น้อยกว่า 5 GB | PO |
| บัญชีสำรอง: เป็นของบุคลากร สสอ. อีกคนหนึ่ง เปิดการยืนยันตัวตนสองชั้น ได้สิทธิ์อ่านโฟลเดอร์ของระบบ และสคริปต์คัดลอกทำงานสำเร็จหนึ่งรอบ | PO และผู้ถือบัญชีสำรอง |
| การตรวจการแชร์ในหน้าตั้งค่าไม่พบการแชร์อื่นนอกจากบัญชีสำรอง | PO |
| หน้าคู่มือและหน้าการคุ้มครองข้อมูลส่วนบุคคลมีเนื้อหาที่ PO ตรวจแล้ว | PO |
| ร่างบันทึกรายการกิจกรรมการประมวลผล และขั้นตอนเมื่อเกิดเหตุละเมิด (ข้อ 10) | Claude Code ร่าง PO ส่งต่อ |
| สถานะของคำถามถึงสำนักงานสาธารณสุขจังหวัดแต่ละข้อ (ข้อ 13) | PO |

ข้อสุดท้ายไม่เป็นเงื่อนไขบังคับ รายงานแสดงว่าข้อใดมีคำตอบแล้ว และ PO ยอมรับข้อที่ยังไม่มีคำตอบด้วยการอนุมัติ

## 7. การเริ่มใช้ข้อมูลจริง

1. Claude Code เปิด PR ที่บันทึกวันเริ่มใช้ข้อมูลจริงใน roadmap พร้อมรายงานความพร้อม
2. PO สั่ง merge PR นั้น คำสั่งนี้คือการอนุมัติการเริ่มใช้ข้อมูลจริง และเป็นการอนุมัติการล้างข้อมูลสมมติของชุดแรก
3. Claude Code รันคำสั่งเริ่มใช้ข้อมูลจริงในชุดแรกหนึ่งครั้ง ([spec ข้อ 8](spec.md#การเริ่มใช้ข้อมูลจริง))
4. Claude Code ตรวจด้วย Playwright ว่าระบบว่าง ไม่มีแถบข้อมูลสมมติ Dashboard สาธารณะปิด หน้าร่างรายงานไม่มีปุ่มให้ AI ช่วยร่าง และผู้ดูแลคนแรกล็อกอินได้
5. Claude Code เลิกเข้าถึงชุดใช้งานจริงตั้งแต่จุดนี้ ก่อนที่ข้อมูลจริงรายการแรกจะถูกกรอก
6. PO เพิ่มผู้ดูแลคนที่สองและผู้ใช้จริงของทุกหน่วยบริการ แล้วแจ้งผู้ใช้เอง
7. PO เปิด Dashboard สาธารณะของชุดใช้งานจริงเองเมื่อได้คำตอบเรื่องมาตรา 10 ของพระราชบัญญัติโรคติดต่อ พ.ศ. 2558
8. PO เปิดการร่างรายงานด้วย AI ของชุดใช้งานจริงเองเมื่อตัดสินใจแล้ว โดยผูกการชำระเงินกับ Gemini API ปิดการเก็บ Logs ในหน้า Logs ของ AI Studio ของโปรเจกต์นั้น ตั้งกุญแจของระดับชำระเงินในค่าตั้งของ Apps Script ของชุดใช้งานจริง แล้วเปิดค่าในหน้าตั้งค่า ตามขั้นตอนที่เตรียมให้ ระหว่างนั้นผู้ดูแลใช้ไฟล์ตั้งต้นได้ ([ADR-0008](adr/0008-delivery-process-and-gates.md) ข้อ 16)

วันแรก: ทุกหน่วยบริการเข้าใช้ได้พร้อมกัน บันทึกเฉพาะเหตุการณ์ที่รับแจ้งตั้งแต่วันนั้น เหตุการณ์ที่ยังอยู่ในระยะเฝ้าระวัง ผู้ดูแลเลือกกรอกย้อนหลังเองได้ หน่วยที่ยังไม่ล็อกอินทำงานต่อได้ เพราะผู้ดูแลส่ง LINE ตามเดิมและบันทึกผลแทนหน่วยบริการได้

## 8. Deploy ขึ้นชุดใช้งานจริง

1. การเปลี่ยนแปลงเข้า `main` ผ่าน PR ตามปกติ และขึ้นชุดทดสอบเอง
2. Claude Code ตรวจชุดทดสอบด้วย Playwright
3. Claude Code เปิด PR จาก `main` เข้า `release` ซึ่งระบุสิ่งที่เปลี่ยน ผลการตรวจในชุดทดสอบ และว่ามี migration หรือบริการของ Google ที่เพิ่มหรือไม่
4. PO สั่ง merge คำสั่งนี้คือการอนุมัติ Deploy ครั้งนั้น ทั้งหน้าเว็บและ API
5. ถ้ามี migration ระบบสำรองก่อน เปิดโหมดปิดปรับปรุงระหว่างเปลี่ยนโครงสร้าง และหยุดถ้าสำรองไม่สำเร็จ
6. Claude Code ตรวจชุดใช้งานจริงได้สองอย่างเท่านั้น: หน้าล็อกอินเปิดได้ และคำขอตรวจรุ่นคืนเลขรุ่นของโค้ดกับโครงสร้างที่ตรงกับ PR
7. ถ้าหน้าเว็บรุ่นใหม่มีปัญหา Cloudflare Pages ย้อนไปรุ่นก่อนได้ทันที API ย้อนด้วยการชี้ deployment กลับไป version ก่อน

วิธีส่งโค้ด API ขึ้น Apps Script ของชุดใช้งานจริงยังไม่ตัดสิน ทางเลือกคือ GitHub Actions หรือคำสั่งที่ PO รันเอง ตัดสินในแผนของช่วงที่ 7 ([spec ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน))

## 9. ข้อผิดพลาดในชุดใช้งานจริง

Claude Code ไม่เปิดสี่อย่างของชุดใช้งานจริง: ไฟล์ Sheet โฟลเดอร์ Drive log ของ Apps Script และหน้าเว็บในฐานะผู้ใช้

1. ผู้ใช้แจ้งรหัสอ้างอิงที่เห็นบนหน้าจอ
2. PO ค้น log ด้วยรหัสนั้น แล้วคัดลอกบรรทัดของ log ให้ Claude Code บรรทัดนั้นอ้างถึงเหตุการณ์และผู้ป่วยด้วยรหัสของแถวเท่านั้น
3. Claude Code ทำซ้ำในชุดทดสอบด้วยข้อมูลสมมติ แก้ แล้วเดินตามข้อ 8
4. ถ้าทำซ้ำไม่ได้โดยไม่เห็นข้อมูลจริง Claude Code หยุดและบอก PO ว่าต้องการข้อเท็จจริงใด PO ตอบด้วยคำบรรยาย ไม่ส่งข้อมูลผู้ป่วย

## 10. เหตุละเมิดข้อมูลส่วนบุคคล

เหตุละเมิดรวมการที่ข้อมูลรั่ว ถูกแก้โดยไม่มีสิทธิ์ ถูกทำลาย และการที่เข้าถึงข้อมูลไม่ได้ ทั้งที่เกิดจากเจตนา ความผิดพลาด และอุบัติเหตุ ([ผลการค้น ข้อ 4.6](research/data-retention-governance-facts.md)) ตัวอย่างของระบบนี้: ไฟล์ฐานข้อมูลหรือโฟลเดอร์รูปถูกแชร์ออกไป บัญชีเจ้าของถูกผู้อื่นเข้า มือถือของผู้ใช้ที่ล็อกอินค้างหาย ไฟล์ส่งออกที่มีชื่อผู้ป่วยถูกส่งผิดคน และการเข้าบัญชีเจ้าของไม่ได้

1. **หยุดเหตุ** ตามชนิด: สั่งบัญชีที่เกี่ยวข้องออกจากระบบทุกเครื่องและระงับบัญชี ยกเลิกการแชร์ เปลี่ยนรหัสผ่านของบัญชีเจ้าของ ปิด Dashboard สาธารณะ หรือเปิดโหมดปิดปรับปรุง
2. **จดข้อเท็จจริง** เวลาที่ทราบเหตุ ข้อมูลของใครและกี่ราย ชนิดของข้อมูล และสิ่งที่ทำไปแล้ว บันทึกความปลอดภัยของระบบมีแถวของการล็อกอิน การส่งออก และการถูกปฏิเสธ
3. **แจ้งผู้ควบคุมข้อมูลและเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล** ตามคำตอบของคำถามข้อ 13
4. **แจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลภายใน 72 ชั่วโมงนับแต่ทราบเหตุ** เว้นแต่เหตุนั้นไม่มีความเสี่ยงต่อสิทธิและเสรีภาพของบุคคล การแจ้งระบุลักษณะของเหตุ ผู้ประสานงาน ผลกระทบที่อาจเกิด และมาตรการที่ใช้ การแจ้งช้าขอยกเว้นความผิดได้ไม่เกิน 15 วันนับแต่ทราบเหตุ
5. **แจ้งเจ้าของข้อมูล**เมื่อความเสี่ยงสูง พร้อมแนวทางเยียวยา
6. บันทึกเหตุเป็น Issue ที่ไม่มีข้อมูลบุคคล แล้วทบทวนมาตรการ

ผู้ตัดสินว่าเหตุใดต้องแจ้ง และผู้ลงนามแจ้ง คือผู้ควบคุมข้อมูล ซึ่งยังเป็น **Not Verified** ว่าเป็นหน่วยงานใด เอกสารนี้ไม่ใช่คำแนะนำทางกฎหมาย

## 11. ย้ายระบบไปบัญชีอื่น

ใช้เมื่อเจ้าของบัญชีย้ายงาน หรือเข้าบัญชีเจ้าของไม่ได้ถาวร Google ไม่ให้โอน deployment ของ Apps Script งานตามเวลา และ Script Properties ไปบัญชีอื่น และการโอนความเป็นเจ้าของไฟล์ระหว่างบัญชีส่วนตัวต้องทำทีละไฟล์โดยผู้รับกดรับ ([ผลการค้น ข้อ 4.4 และ 4.5](research/backup-environment-facts.md)) การย้ายจึงเป็นการสร้างชุดใหม่ในบัญชีใหม่ แล้วกู้คืนข้อมูลเข้าไป

สิ่งที่ผูกกับบัญชีของเจ้าของเดิม และต้องมีของใหม่

| สิ่ง | ของใหม่ |
|---|---|
| ไฟล์ฐานข้อมูล | คัดลอกจากชุดสำรองล่าสุดของบัญชีสำรอง หรือจากโฟลเดอร์ของระบบถ้ายังเปิดได้ |
| รูปถ่าย | คัดลอกจากโฟลเดอร์ของระบบถ้ายังเปิดได้ ถ้าบัญชีเดิมถูกลบ รูปหาย |
| Apps Script project งานตามเวลา และ Script Properties | สร้างใหม่จากโค้ดใน repository แล้วตั้งค่าใหม่ ที่อยู่ของ API เปลี่ยน |
| OAuth client | สร้างใหม่ในโปรเจกต์ Google Cloud ของบัญชีใหม่ |
| Cloudflare Pages | ตั้งค่าที่อยู่ของ API และ client ID ใหม่ ถ้าบัญชี Cloudflare เป็นของเจ้าของเดิม ต้องสร้างโปรเจกต์ใหม่ และที่อยู่ของหน้าเว็บเปลี่ยน |
| Repository | เป็นสาธารณะ คัดลอกได้ |

การสร้างชุดทดสอบในช่วงที่ 7 ซ้อมขั้นตอนเหล่านี้ภายในบัญชีเดียวกัน การย้ายข้ามบัญชีจริงเป็น **Not Verified** พิสูจน์ได้ด้วยการทำหนึ่งครั้งด้วยบัญชีสำรองกับข้อมูลสมมติ

## 12. งานประจำปี

PO หรือผู้ดูแลทำปีละครั้ง พร้อมการนำประชากรของปีใหม่เข้า

1. ทบทวนรายการผู้ใช้ ระงับบัญชีของคนที่ย้ายหรือไม่ได้ใช้ รายการผู้ใช้แสดงเวลาที่เข้าระบบล่าสุด
2. ผู้ถือบัญชีสำรองล็อกอินบัญชีนั้น และตรวจว่าสำเนาล่าสุดมีอายุไม่เกิน 8 วัน Google ลบบัญชีส่วนตัวที่ไม่มีการใช้งาน 2 ปีได้ และเอกสารไม่รับรองว่าการทำงานของสคริปต์นับเป็นการใช้งาน
3. ตรวจว่า OAuth client ของชุดทดสอบยังอยู่ Google ลบ client ที่ไม่ถูกใช้ 6 เดือน โดยแจ้งทางอีเมลล่วงหน้า 30 วัน
4. ตรวจว่ารหัสสำรองของบัญชีเจ้าของยังอยู่ที่สำนักงาน และเบอร์โทรกู้คืนยังเป็นเบอร์ที่ใช้อยู่
5. ทดลองกู้คืนในชุดทดสอบหนึ่งครั้ง (ข้อ 3)
6. ตรวจว่ามีเหตุการณ์ใดครบ[ระยะเวลาเก็บข้อมูล](spec.md#ระยะเวลาเก็บข้อมูล) ซึ่งจะเกิดครั้งแรกในปี พ.ศ. 2579
7. เมื่อการร่างรายงานด้วย AI เปิดอยู่ ตรวจว่ารุ่นของ Gemini ที่ตั้งไว้ยังเปิดให้บริการ และเครดิตที่เติมไว้ยังไม่หมดอายุ เครดิตหมดอายุใน 12 เดือน และเมื่อเครดิตหมด การร่างด้วย AI ใช้ไม่ได้จนกว่าจะเติม ([ผลการค้นเรื่องการร่างด้วย AI ข้อ 3.1 และ 3.4](research/ai-report-drafting-facts.md))

## 13. คำถามถึงสำนักงานสาธารณสุขจังหวัด

PO ถามนิติกรหรือผู้รับผิดชอบด้านข้อมูลของสำนักงานสาธารณสุขจังหวัดครั้งเดียวทั้งหกข้อ แล้วบันทึกคำตอบใน [spec ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน) ผ่าน PR

1. การที่ สสอ. เผยแพร่จำนวนรวมรายตำบลอยู่ในขอบเขตของมาตรา 10 ของพระราชบัญญัติโรคติดต่อ พ.ศ. 2558 หรือไม่ ([spec ข้อ 7](spec.md#ความเสี่ยงที่ยอมรับ-และข้อที่ยังไม่ยืนยัน))
2. ผู้ควบคุมข้อมูลส่วนบุคคลของงานควบคุมโรคของ สสอ. คือหน่วยงานใด และเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคลที่ต้องระบุในคำแจ้งและในการแจ้งเหตุละเมิดคือใคร
3. ข้อมูลผู้ป่วยที่ สสอ. ได้จากโรงพยาบาลหรือหน่วยบริการ ต้องแจ้งรายละเอียดแก่ผู้ป่วยตามมาตรา 25 ของพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 หรือไม่ และแจ้งด้วยวิธีใด
4. ทะเบียนเหตุการณ์และข้อมูลผู้ป่วยในระบบของ สสอ. มีอายุการเก็บตามระเบียบใด ถือเป็นหนังสืออิเล็กทรอนิกส์ตามระเบียบงานสารบรรณหรือไม่ และใครมีอำนาจสั่งทำลายเมื่อครบกำหนด
5. นโยบายความมั่นคงปลอดภัยสารสนเทศของกระทรวงสาธารณสุขมีข้อกำหนดเรื่องการเก็บข้อมูลผู้ป่วยในบัญชีส่วนบุคคลหรือบริการคลาวด์ของต่างประเทศหรือไม่ PO ยอมรับความเสี่ยงของที่เก็บข้อมูลแล้วใน [ADR-0001](adr/0001-rebuild-on-apps-script-and-sheets.md) คำถามนี้ถามว่ามีกฎที่ห้ามหรือไม่ ซึ่งการค้นยังอ่านเอกสารนั้นไม่ได้
6. การส่งข้อมูลของเหตุการณ์ที่ไม่มีชื่อ บ้านเลขที่ และชื่อสถานที่ ให้บริการ AI ของต่างประเทศเพื่อร่างรายงานสอบสวน โดยผู้ให้บริการไม่นำไปพัฒนาบริการแต่เก็บไว้ 55 วัน ทำได้หรือไม่ และต้องมีข้อตกลงหรือการประเมินใดก่อน ([spec ข้อ 4](spec.md#ร่างรายงานสอบสวน)) ข้อนี้ต้องมีคำตอบก่อนเปิดการร่างรายงานด้วย AI ของชุดใช้งานจริง ไม่ใช่ก่อนเริ่มใช้ข้อมูลจริง
