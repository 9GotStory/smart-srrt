# ADR-0001: สร้างใหม่ทั้งหมดบน Apps Script และ Google Sheets เดิม

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16

## บริบท

การทดสอบระบบเดิมบน browser เมื่อ 12 พฤศจิกายน 2026 ผ่านทุกข้อในด้านการทำงาน แต่ Product Owner (PO) พบว่าหน้าจอใช้งานไม่ได้จริง สาเหตุอยู่ที่โครงสร้าง ไม่ใช่ที่หน้าจออย่างเดียว

- สถานะของเหตุการณ์คำนวณจากช่องในฟอร์มยาวหนึ่งฟอร์ม ไม่มีขั้นตอนให้กด
- ระบบมอบหมายงานให้ได้เฉพาะผู้ใช้ที่ล็อกอิน แต่คนลงพื้นที่คือ รพ.สต.
- โมดูลไข้เลือดออก (D331) มี 7 ตารางและสิทธิ์รายเหตุการณ์ของตัวเอง อ่านข้อมูลเหตุการณ์ทางเดียว และทำให้ต้องบันทึกเรื่องเดียวกันสองที่
- การอนุมัติหลายชั้นของ D331 ออกแบบสำหรับองค์กรที่มีหลายฝ่ายลงนาม แต่ PO เป็นทั้งเจ้าของระบบและผู้ใช้งาน

PO ยืนยันว่าระบบยังอยู่ในช่วงพัฒนาและยังไม่มีข้อมูลจริง เอกสารของโครงการเดิมระบุว่าไม่มี Production

## การตัดสินใจ

1. สร้างโครงสร้างข้อมูล server และหน้าเว็บใหม่ทั้งหมด ตาม [`../spec.md`](../spec.md) และ [`../schema.md`](../schema.md)
2. ใช้ Google Apps Script และ Google Sheets เป็น backend ต่อ ในบัญชี Gmail ส่วนตัวของ PO
3. ใช้ Apps Script project และไฟล์ Sheet เดิม ก่อนใช้ ให้คัดลอกไฟล์ Sheet เป็นชุดสำรอง ลบแท็บของระบบเก่า และเก็บเฉพาะข้อมูลที่ใช้ต่อ
4. ไม่ย้ายเหตุการณ์และผู้ใช้จากระบบเก่า
5. เขียนใน repository เดิม ทำ tag `legacy-v1` แล้วลบโค้ดเก่าออกจากสาขาหลัก
6. ยกเลิกงาน D331 F04–F08 และการตัดสินใจที่ค้างของ D331 (D2/P1/P2/S1/S2/C1/C2)

## ผลที่ตามมา

- ระบบเก่าหยุดให้บริการเมื่อ deploy ระบบใหม่ครั้งแรก กู้คืนได้จากประวัติเวอร์ชันของ Apps Script และ tag `legacy-v1`
- ไม่มีค่าใช้จ่ายเพิ่ม และไม่มีเซิร์ฟเวอร์ให้ดูแล
- ข้อจำกัดของ Apps Script ยังอยู่: คำขอหนึ่งครั้งใช้เวลาเป็นวินาที และมีโควตารายวันของบัญชี
- **ความเสี่ยงที่ PO ยอมรับเมื่อ 16 พฤศจิกายน 2026:** ข้อมูลสุขภาพอยู่ในบัญชี Gmail ส่วนตัว ถ้าเข้าบัญชีไม่ได้หรือเจ้าของบัญชีย้ายงาน ระบบและข้อมูลไปกับบัญชี มาตรการลดความเสี่ยงคือสำรองข้อมูลทุกสัปดาห์ และเพิ่มบัญชี Google สำรองก่อนเริ่มใช้ข้อมูลจริง
- ฐานของการเก็บข้อมูลผู้ป่วยตามที่ PO ระบุ: ใช้เพื่อการเฝ้าระวังและควบคุมโรค ซึ่งเป็นการให้บริการด้านสุขภาพของหน่วยงานสาธารณสุข

## ทางเลือกที่ไม่เลือก

- **ออกแบบเฉพาะหน้าจอใหม่บน server เดิม** ไม่เลือก เพราะการมอบหมายงานให้ รพ.สต. และการรวมไข้เลือดออกเข้ากับเหตุการณ์ต้องเปลี่ยนโครงสร้างข้อมูล
- **ย้ายไปฐานข้อมูลและเซิร์ฟเวอร์จริง** ไม่เลือก เพราะมีค่าใช้จ่ายและงานดูแล ขณะที่ปริมาณงานระดับอำเภออยู่ในกำลังของ Sheets
- **สร้าง Apps Script project และไฟล์ Sheet ใหม่** ไม่เลือก PO ต้องการใช้ ID เดิมและมีลิงก์เดียว
- **ใช้บัญชี Google กลางของหน่วยงาน** ไม่เลือกในตอนนี้ PO เลือกบัญชีส่วนตัวและยอมรับความเสี่ยง
