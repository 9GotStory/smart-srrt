# ADR-0004: บทบาท 3 แบบ และการมองเห็นตามหน่วยงาน

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16

## บริบท

ระบบเก่ามี 4 บทบาท (Super Admin, Manager, Admin, Staff) ซึ่งสองบทบาทบนมีสิทธิ์เท่ากัน และโมดูล D331 เพิ่มสิทธิ์รายเหตุการณ์ที่ต้องมีผู้อนุมัติอีกคน ผู้ใช้ทุกคนที่ล็อกอินเห็นเหตุการณ์ทั้งอำเภอ

การทำงานจริงตามที่ PO อธิบาย: เจ้าหน้าที่ สสอ. เป็นผู้จัดการทั้งหมด แจ้ง รพ.สต. ผ่าน LINE และทำงานร่วมกัน

## การตัดสินใจ

1. มี 3 บทบาท: `admin` (สสอ.), `unit` (รพ.สต.) และ `viewer` (ผู้ดู)
2. ผู้ใช้ `unit` ผูกกับหน่วยงานหนึ่งแห่ง หน่วยหนึ่งมีผู้ใช้ได้หลายคน บัญชีเป็นรายคน
3. ผู้ใช้ `unit` เห็นเฉพาะเหตุการณ์ที่หน่วยของตนแจ้ง และงานที่มอบหมายให้หน่วยของตน
4. สิทธิ์ของ `unit` มาจากการมอบหมายงาน ไม่มีการออกสิทธิ์รายเหตุการณ์แยกต่างหาก
5. มี `admin` ได้มากกว่าหนึ่งคน
6. `viewer` เป็นบุคลากรของ สสอ. อ่านข้อมูลของเหตุการณ์ได้เท่ากับ `admin` และแก้ไขไม่ได้
7. กฎทั้งหมดบังคับที่ server ตามตารางใน [`../schema.md` ข้อ 6](../schema.md#6-กฎสิทธิ์การมองเห็น) คำขอนอกขอบเขตได้คำตอบว่าไม่พบ

## ผลที่ตามมา

- รพ.สต. บันทึกผลเอง ผู้ดูแลไม่ต้องคัดลอกจาก LINE และระบบรู้ว่าใครบันทึก
- ทุกจุดที่อ่านข้อมูลต้องกรองตามหน่วยงานของผู้ใช้ การทดสอบต้องมีกรณีที่ รพ.สต. หนึ่งพยายามเข้าถึงข้อมูลของอีกแห่ง
- ผู้ดูแลต้องดูแลบัญชีของ รพ.สต. และทะเบียนหมู่บ้านที่แต่ละแห่งรับผิดชอบ
- การเปลี่ยนหน่วยของผู้ใช้เปลี่ยนสิ่งที่ผู้ใช้นั้นเห็นทันที

## ทางเลือกที่ไม่เลือก

- **ผู้ใช้คนเดียวที่ สสอ. และ รพ.สต. ไม่ล็อกอิน** เป็นข้อเสนอแรก ไม่เลือก เพราะผู้ดูแลต้องพิมพ์ผลจาก LINE ลงระบบแทนทุกครั้ง
- **หนึ่งบัญชีต่อหนึ่ง รพ.สต.** ไม่เลือก เพราะไม่รู้ว่าใครบันทึก และเมื่อคนย้ายออกต้องเปลี่ยนบัญชีของทั้งหน่วย
- **คง 4 บทบาทและสิทธิ์รายเหตุการณ์ของ D331** ไม่เลือก เพราะไม่ตรงกับคนที่ทำงานจริง
