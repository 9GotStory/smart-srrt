# ADR-0008: วิธีส่งมอบ และจุดที่ต้องขออนุมัติ

* สถานะ: Proposed
* วันที่: 2026-11-16

## บริบท

โครงการเดิมมีจุดอนุมัติจำนวนมาก: แผน, Issue, Merge, Backup, Deploy, Browser UAT และการตัดสินใจเชิงนโยบายของ D331 อีก 7 เรื่องที่รอผู้ลงนามซึ่งไม่มีตัวตนในบริบทของ สสอ. หนึ่งแห่ง ผลคือ D331 ค้างอยู่ที่ข้อมูลสมมติ

PO เป็นทั้งเจ้าของระบบและผู้ใช้งาน ระบบยังไม่มีข้อมูลจริง และ PO เลือกใช้ระบบชุดเดียวในช่วงพัฒนา

## การตัดสินใจ

### จุดที่ PO ต้องอนุมัติ

| เรื่อง | เมื่อไร |
|---|---|
| แผนของแต่ละช่วงใน [roadmap](../roadmap.md) | ก่อนสร้าง Issue และเริ่มเขียนโค้ด |
| Merge | ทุก PR หลังตรวจโค้ดและ CI ผ่าน |
| Deploy ขึ้นชุดใช้งานจริง | ทุกครั้ง หลังเริ่มใช้ข้อมูลจริง |
| การเริ่มใช้ข้อมูลจริง | ครั้งเดียว ตามช่วงที่ 6 ของ roadmap |
| การเรียก Gemini จริง | ก่อนเปิดใช้ความสามารถ AI ในรุ่นถัดไป |
| การลบหรือล้างข้อมูลใน Sheet หรือ Drive | ทุกครั้ง หลังมีชุดสำรองที่ตรวจแล้ว |

### ช่วงพัฒนา

1. มีระบบชุดเดียว ใช้ข้อมูลสมมติเท่านั้น
2. ตราบใดที่ระบบมีแต่ข้อมูลสมมติ การอนุมัติ Merge ของ PO ครอบคลุมการ Deploy ขึ้นชุดนี้และการตรวจบน browser ด้วย Playwright
3. ข้อมูลสมมติต้องแยกจากข้อมูลจริงได้ชัดเจน เช่น ชื่อหน่วยงานและชื่อบุคคลที่เห็นได้ว่าสมมติ

### หลังเริ่มใช้ข้อมูลจริง

4. มีสองชุดที่แยกกัน: ชุดใช้งานจริง และชุดทดสอบและพัฒนาที่คัดลอกจากโครงสร้างและข้อมูลสมมติ
5. Claude Code ทำงานในชุดทดสอบเท่านั้น ไม่อ่านและไม่เขียนชุดใช้งานจริง
6. ข้อมูลจริงไม่ถูกคัดลอกมาที่ชุดทดสอบ การทดสอบ และ repository

### วิธีทำงาน

7. งานพัฒนาและตรวจโค้ดทำด้วย Claude Code ตาม [`CLAUDE.md`](../../CLAUDE.md)
8. ทุกช่วงเดินตามลำดับ: แผน → PO อนุมัติ → Issue → พัฒนาแบบ test-first → PR → ตรวจโค้ด → PO อนุมัติ Merge → Deploy และตรวจบน browser
9. ห้าม push ตรงเข้า `main`

## ผลที่ตามมา

- ช่วงพัฒนาเดินเร็วขึ้น เพราะ Merge หนึ่งครั้งนำไปถึงระบบที่ลองใช้ได้
- การตัดสินใจที่ค้างของ D331 (D2/P1/P2/S1/S2/C1/C2) ถูกแทนด้วย ADR ชุดนี้ ซึ่ง PO เป็นผู้ตัดสิน
- ข้อ 2 หมดผลทันทีที่ PO อนุมัติการเริ่มใช้ข้อมูลจริง
- ไม่มีผู้ตรวจอิสระนอกจาก PO ความถูกต้องพึ่งการทดสอบอัตโนมัติ การตรวจโค้ด และการทดลองใช้ของ รพ.สต. ก่อนเริ่มใช้จริง

## ทางเลือกที่ไม่เลือก

- **คงจุดอนุมัติเดิมทั้งหมด** ไม่เลือก ด้วยเหตุผลในบริบท
- **แยกชุดทดสอบกับชุดใช้งานจริงตั้งแต่วันแรก** เป็นข้อเสนอแรก PO เลือกใช้ชุดเดียวจนกว่าระบบจะผ่าน
- **ขออนุมัติ Deploy แยกทุกครั้งตั้งแต่ช่วงพัฒนา** ไม่เลือก เพราะชุดเดียวที่มีแต่ข้อมูลสมมติไม่มีความเสี่ยงที่จุดอนุมัตินี้ป้องกัน
