# ADR-0006: ข้อมูลผู้ป่วย และการเปิดเผยต่อสาธารณะ

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16

## บริบท

ระบบเก็บข้อมูลสุขภาพของบุคคล ฐานข้อมูลอยู่ในบัญชี Gmail ส่วนตัว และ repository เป็นสาธารณะ PO ระบุว่าการใช้ข้อมูลผู้ป่วยนี้เป็นการใช้เพื่อการให้บริการด้านสุขภาพ และยอมรับความเสี่ยงของที่เก็บข้อมูล

ข้อเสนอแรกคือไม่เก็บชื่อผู้ป่วย แต่ในหมู่บ้าน เจ้าหน้าที่ตามหาผู้ป่วยด้วยชื่อ ถ้าระบบไม่มีชื่อ ชื่อจะถูกพิมพ์ส่งกันในกลุ่ม LINE ซึ่งระบบควบคุมไม่ได้

Dashboard สาธารณะของระบบเก่าแสดงตัวเลขถึงระดับหมู่บ้าน และไม่ซ่อนค่าที่มีจำนวนน้อย คนในพื้นที่อาจเดาตัวผู้ป่วยได้

## การตัดสินใจ

### ข้อมูลผู้ป่วย

1. เก็บชื่อ-สกุล อายุ เพศ บ้านเลขที่ หมู่บ้าน วันเริ่มป่วย การวินิจฉัย เวลาที่วินิจฉัย และสถานที่รักษา
2. ไม่เก็บเลขบัตรประชาชนและ HN
3. ชื่อและบ้านเลขที่เห็นได้เฉพาะบุคลากรของ สสอ. (`admin` และ `viewer`) และ `unit` ที่มีงานผูกกับผู้ป่วยรายนั้น รูปถ่ายเห็นได้เฉพาะบุคลากรของ สสอ. และ `unit` เจ้าของงานที่รูปนั้นแนบอยู่
4. ข้อความ LINE ที่ระบบเตรียมไม่มีชื่อและบ้านเลขที่ มีลิงก์ที่ต้องล็อกอินจึงจะเห็น
5. ช่องข้อความอิสระและหน้าแนบรูปมีคำเตือนไม่ให้ใส่ชื่อ เอกสารที่มีชื่อ หรือใบหน้าผู้ป่วย
6. รับเฉพาะรูปถ่าย ไม่รับไฟล์เอกสาร รูปเก็บในโฟลเดอร์ส่วนตัวของระบบ ไม่มีลิงก์สาธารณะ
7. Log, audit log, commit, Issue และ PR ไม่มีชื่อผู้ป่วย ข้อความบรรยายเหตุการณ์ token หรือ ID ของไฟล์จริง

### Dashboard สาธารณะ

8. แสดงเฉพาะจำนวนรวมตามโรค เดือน และตำบล
9. นับเฉพาะเหตุการณ์ที่ตรวจสอบแล้วว่าจริง
10. ช่องที่มีจำนวน 1–4 แสดงเป็น "<5" และยอดรวมต้องไม่ทำให้คำนวณย้อนกลับได้

### ข้อมูลในช่วงพัฒนา

11. ใช้ข้อมูลสมมติเท่านั้น จนกว่า PO จะอนุมัติการเริ่มใช้ข้อมูลจริง ([ADR-0008](0008-delivery-process-and-gates.md))

## ผลที่ตามมา

- ระบบถือข้อมูลที่ระบุตัวบุคคลได้ การรั่วของไฟล์ Sheet หรือบัญชีเจ้าของมีผลกระทบสูง
- บัญชี `viewer` อ่านข้อมูลได้เท่ากับ `admin` จึงต้องดูแลการให้และถอนบัญชีนี้เข้มเท่ากัน
- ระบบตรวจเนื้อหาในรูปและข้อความอิสระไม่ได้ ข้อ 5 พึ่งการเตือนและวินัยของผู้ใช้
- การซ่อนค่าต่ำกว่า 5 ทำให้ Dashboard สาธารณะของอำเภอเล็กมีช่อง "<5" จำนวนมาก
- ยังไม่ได้กำหนดระยะเวลาเก็บข้อมูล PO ต้องตัดสินก่อนเริ่มใช้ข้อมูลจริง

## ทางเลือกที่ไม่เลือก

- **ไม่เก็บชื่อผู้ป่วย** ไม่เลือก ด้วยเหตุผลในบริบท
- **`viewer` ไม่เห็นชื่อ บ้านเลขที่ และรูปถ่าย** เป็นข้อเสนอแรก PO ตัดสินเมื่อ 16 พฤศจิกายน 2026 ว่าบุคลากรของ สสอ. ควรเห็นทั้งหมด
- **เก็บเลขบัตรประชาชนเพื่อกันผู้ป่วยซ้ำ** ไม่เลือก งานในระบบนี้ไม่ต้องใช้ และเพิ่มผลกระทบเมื่อข้อมูลรั่ว
- **ไม่มี Dashboard สาธารณะ** เป็นข้อเสนอแรก PO เลือกให้มี
- **Dashboard สาธารณะระดับหมู่บ้าน** ไม่เลือก จำนวนต่อช่องน้อยเกินไป
