# ADR-0006: ข้อมูลผู้ป่วย และการเปิดเผยต่อสาธารณะ

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16
* แก้ไข: 2026-11-17 เพิ่มข้อ 12 ถึง 15 และผลที่ตามมา เมื่อลงรายละเอียด Dashboard สาธารณะ ตาม[ผลการค้น](../research/public-dashboard-facts.md)

## บริบท

ระบบเก็บข้อมูลสุขภาพของบุคคล ฐานข้อมูลอยู่ในบัญชี Gmail ส่วนตัว และ repository เป็นสาธารณะ PO ระบุว่าการใช้ข้อมูลผู้ป่วยนี้เป็นการใช้เพื่อการให้บริการด้านสุขภาพ และยอมรับความเสี่ยงของที่เก็บข้อมูล

ข้อเสนอแรกคือไม่เก็บชื่อผู้ป่วย แต่ในหมู่บ้าน เจ้าหน้าที่ตามหาผู้ป่วยด้วยชื่อ ถ้าระบบไม่มีชื่อ ชื่อจะถูกพิมพ์ส่งกันในกลุ่ม LINE ซึ่งระบบควบคุมไม่ได้

Dashboard สาธารณะของระบบเก่าแสดงตัวเลขถึงระดับหมู่บ้าน และไม่ซ่อนค่าที่มีจำนวนน้อย คนในพื้นที่อาจเดาตัวผู้ป่วยได้

## การตัดสินใจ

### ข้อมูลผู้ป่วย

1. เก็บชื่อ-สกุล อายุ เพศ บ้านเลขที่ หมู่บ้าน วันเริ่มป่วย การวินิจฉัย เวลาที่วินิจฉัย และสถานที่รักษา
2. ไม่เก็บเลขบัตรประชาชนและ HN
3. ชื่อและบ้านเลขที่เห็นได้เฉพาะบุคลากรของ สสอ. (`admin` และ `viewer`) และ `unit` ที่มีงานผูกกับผู้ป่วยรายนั้นหรือเป็นผู้เพิ่มผู้ป่วยรายนั้นเอง (ส่วนของผู้เพิ่มแก้ไขเมื่อ 16 พฤศจิกายน 2026 เมื่อ PO ให้หน่วยบริการเพิ่มผู้ป่วยได้) รูปถ่ายเห็นได้เฉพาะบุคลากรของ สสอ. และ `unit` เจ้าของงานที่รูปนั้นแนบอยู่
4. ข้อความ LINE ที่ระบบเตรียมไม่มีชื่อและบ้านเลขที่ มีลิงก์ที่ต้องล็อกอินจึงจะเห็น
5. ช่องข้อความอิสระและหน้าแนบรูปมีคำเตือนไม่ให้ใส่ชื่อ เอกสารที่มีชื่อ หรือใบหน้าผู้ป่วย
6. รับเฉพาะรูปถ่าย ไม่รับไฟล์เอกสาร รูปเก็บในโฟลเดอร์ส่วนตัวของระบบ ไม่มีลิงก์สาธารณะ
7. Log, audit log, commit, Issue และ PR ไม่มีชื่อผู้ป่วย ข้อความบรรยายเหตุการณ์ token หรือ ID ของไฟล์จริง

### Dashboard สาธารณะ

8. แสดงเฉพาะจำนวนรวมตามโรค เดือน และตำบล
9. นับเฉพาะเหตุการณ์ที่ตรวจสอบแล้วว่าจริง
10. ช่องที่มีจำนวน 1–4 แสดงเป็น "<5" และยอดรวมต้องไม่ทำให้คำนวณย้อนกลับได้

### ข้อมูลในช่วงพัฒนา

11. ใช้ข้อมูลสมมติเท่านั้น จนกว่า PO จะอนุมัติการเริ่มใช้ข้อมูลจริง ([ADR-0008](0008-delivery-process-and-gates.md))

### Dashboard สาธารณะ: ข้อที่เพิ่มเมื่อ 17 พฤศจิกายน 2026

ข้อ 12 ถึง 15 กำหนดวิธีทำตามข้อ 8 ถึง 10 รายละเอียดอยู่ใน [spec ข้อ 7](../spec.md#7-dashboard-สาธารณะ)

12. server ส่งให้ผู้ที่ไม่ล็อกอินเพียงตารางเดียว คือจำนวนของแต่ละโรค ตำบล และเดือน ที่ซ่อนค่าแล้ว ยอดรวมทุกตัวคำนวณจากช่องที่แสดงแล้ว และยอดรวมที่มีช่องซ่อนอยู่แสดงเป็นช่วง ค่า 0 แสดงเป็น 0
13. ตัวเลขสาธารณะคำนวณสัปดาห์ละครั้งแล้วเก็บไว้ คำขอสาธารณะไม่อ่านตารางเหตุการณ์และผู้ป่วย
14. โรคติดต่ออันตรายไม่แสดงชื่อเสมอ โรคอื่นแสดงชื่อเมื่อผู้ดูแลเลือก โรคที่ไม่แสดงชื่อนับรวมเป็น "โรคอื่น ๆ"
15. ผู้ดูแลปิด Dashboard สาธารณะได้เองทันที

## ผลที่ตามมา

- ระบบถือข้อมูลที่ระบุตัวบุคคลได้ การรั่วของไฟล์ Sheet หรือบัญชีเจ้าของมีผลกระทบสูง
- บัญชี `viewer` อ่านข้อมูลได้เท่ากับ `admin` จึงต้องดูแลการให้และถอนบัญชีนี้เข้มเท่ากัน
- ระบบตรวจเนื้อหาในรูปและข้อความอิสระไม่ได้ ข้อ 5 พึ่งการเตือนและวินัยของผู้ใช้
- การซ่อนค่าต่ำกว่า 5 ทำให้ Dashboard สาธารณะของอำเภอเล็กมีช่อง "<5" จำนวนมาก
- ยังไม่ได้กำหนดระยะเวลาเก็บข้อมูล PO ต้องตัดสินก่อนเริ่มใช้ข้อมูลจริง
- ยอดรวมทั้งปีของโรคที่มีช่องซ่อนอยู่มากเป็นช่วงกว้าง และตัวเลขสาธารณะช้ากว่าข้อมูลจริงได้ถึงหนึ่งสัปดาห์
- สองตำบลของอำเภอสองมีประชากรต่ำกว่า 5,000 คน ซึ่งเล็กกว่าพื้นที่ที่แหล่งข้อมูลต่างประเทศยอมรับสำหรับตัวเลขโรคติดต่อรายสัปดาห์ PO ยอมรับความเสี่ยงนี้เมื่อ 17 พฤศจิกายน 2026 ([spec ข้อ 7](../spec.md#ความเสี่ยงที่ยอมรับ-และข้อที่ยังไม่ยืนยัน))
- ไม่พบบทบัญญัติที่ห้ามหรืออนุญาตให้ สสอ. เผยแพร่จำนวนรวมรายตำบล เรื่องนี้เป็น **Not Verified** และ Dashboard สาธารณะของชุดใช้งานจริงปิดอยู่จนกว่า PO ได้คำตอบจากนิติกรหรือสำนักงานสาธารณสุขจังหวัด

## ทางเลือกที่ไม่เลือก

- **ไม่เก็บชื่อผู้ป่วย** ไม่เลือก ด้วยเหตุผลในบริบท
- **`viewer` ไม่เห็นชื่อ บ้านเลขที่ และรูปถ่าย** เป็นข้อเสนอแรก PO ตัดสินเมื่อ 16 พฤศจิกายน 2026 ว่าบุคลากรของ สสอ. ควรเห็นทั้งหมด
- **เก็บเลขบัตรประชาชนเพื่อกันผู้ป่วยซ้ำ** ไม่เลือก งานในระบบนี้ไม่ต้องใช้ และเพิ่มผลกระทบเมื่อข้อมูลรั่ว
- **ไม่มี Dashboard สาธารณะ** เป็นข้อเสนอแรก PO เลือกให้มี
- **Dashboard สาธารณะระดับหมู่บ้าน** ไม่เลือก จำนวนต่อช่องน้อยเกินไป
- **ซ่อน 1–4 แล้วแสดงยอดรวมจริง** ไม่เลือก ผู้อ่านหักลบหาช่องที่ซ่อนได้ และแหล่งข้อมูลระบุว่าหน่วยงานสถิติสุขภาพของสหรัฐเลิกใช้แบบนี้
- **ซ่อนช่องอื่นเพิ่มเพื่อกันการหักลบ** ไม่เลือก ต้องมีการตรวจหลังซ่อนทุกครั้ง และยังกันการเทียบระหว่างตารางไม่ได้
- **ซ่อนค่า 0 รวมกับ 1–4** ไม่เลือก หน้าจะบอกไม่ได้ว่าตำบลใดไม่มีเหตุการณ์
- **คำนวณทุกครั้งที่เปิด หรือเผยแพร่รายวัน** ไม่เลือก การเปลี่ยนของช่องหนึ่งชี้ไปที่ผู้ป่วยรายเดียวได้ง่าย
- **รวมตำบลขนาดเล็กกับตำบลข้างเคียง** ไม่เลือก คนในตำบลจะหาตำบลของตนไม่เจอ
- **เกณฑ์ 10 ตามหน่วยงานของสหรัฐ** ไม่เลือก ช่องเกือบทั้งหมดของอำเภอขนาดนี้จะถูกซ่อน
