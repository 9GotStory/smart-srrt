# ADR-0003: เข้าสู่ระบบด้วย Google และตรวจอีเมลกับตารางผู้ใช้

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16

## บริบท

ระบบเก่าเก็บรหัสผ่านของตัวเอง มีหน้าสมัครสมาชิกและรออนุมัติ PO ต้องการให้ผู้ใช้เข้าด้วยบัญชี Google และให้ สสอ. เป็นผู้กำหนดว่าใครเข้าได้

## การตัดสินใจ

1. เข้าสู่ระบบด้วยบัญชี Google เท่านั้น ระบบไม่เก็บรหัสผ่าน และไม่มีหน้าสมัครเอง
2. หน้าเว็บขอ **ID token** จาก Google แล้วส่งให้ server
3. server ตรวจ ID token กับ Google และยอมรับเมื่อครบทุกข้อ
   - token ออกให้ OAuth client ของระบบนี้ (ค่า `aud` ตรงกับ client ID ที่ตั้งไว้)
   - token ยังไม่หมดอายุ
   - Google ยืนยันอีเมลแล้ว (`email_verified`)
4. server ค้นผู้ใช้ในตาราง `users` ด้วย `google_sub` ถ้าเป็นการเข้าครั้งแรกให้ค้นด้วยอีเมลแล้วบันทึก `google_sub`
5. ผู้ใช้ที่ไม่พบ หรือมี `status` เป็น `suspended` ถูกปฏิเสธด้วยข้อความเดียวกัน
6. เมื่อผ่าน server ออก session token แบบสุ่ม อายุ 7 วัน และเก็บเฉพาะค่า hash ของ token
7. ทุกคำขอตรวจ session และ `status` ของผู้ใช้ใหม่ทุกครั้ง การระงับบัญชีจึงมีผลทันทีบนทุกเครื่อง
8. ระบบขอเฉพาะตัวตนและอีเมลจาก Google ไม่ขอสิทธิ์เข้า Drive หรือ Sheets ของผู้ใช้

## ผลที่ตามมา

- ไม่มีรหัสผ่านให้รั่ว และไม่ต้องทำหน้ารีเซ็ตรหัสผ่าน
- ผู้ใช้ทุกคนต้องมีบัญชี Google
- PO ต้องสร้าง OAuth client ใน Google Cloud หนึ่งครั้ง
- server ตรวจ ID token ด้วยการถามบริการของ Google ทุกครั้งที่ล็อกอิน การล็อกอินจึงช้ากว่าคำขออื่น และใช้ไม่ได้เมื่อบริการนั้นขัดข้อง
- ถ้าบัญชีผู้ดูแลทุกบัญชีเข้าไม่ได้ เจ้าของไฟล์ Sheet แก้ตาราง `users` โดยตรงได้
- ถ้า Google ขัดข้อง ไม่มีใครเข้าระบบได้ ซึ่งเป็นจริงกับทั้งระบบอยู่แล้ว เพราะ backend อยู่บน Google

### สิ่งที่ยังไม่ได้พิสูจน์

การล็อกอินเมื่อเปิดลิงก์จากภายในแอป LINE บนมือถือ PO รายงานว่าใช้ได้กับโปรเจกต์อ้างอิง แต่ยังไม่ได้ทดสอบกับระบบนี้ และขั้นตอนขอ ID token บนหน้าเว็บอาจต่างจากที่โปรเจกต์อ้างอิงใช้ รายงานนั้นจึงใช้แทนการทดสอบไม่ได้ ช่วงที่ 1 ของ [roadmap](../roadmap.md) ต้องทดสอบบนมือถือจริง ถ้าไม่ผ่าน ทางเลือกแรกคือทำลิงก์ให้เปิดในเบราว์เซอร์ของเครื่อง

## ทางเลือกที่ไม่เลือก

- **รหัสผ่านของระบบ หรือมีทั้งสองแบบ** ไม่เลือก รหัสผ่านสำรองไม่ช่วยเมื่อ Google ขัดข้อง และเพิ่มสิ่งที่ต้องป้องกัน
- **ส่ง access token แล้วให้ server ถามข้อมูลผู้ใช้จาก Google** ไม่เลือก เพราะ access token ไม่ได้พิสูจน์ว่าออกให้แอปของเรา token ที่ผู้ใช้ให้แอปอื่นไว้อาจถูกนำมาใช้เข้าระบบนี้ได้ ID token ที่ตรวจ `aud` ปิดช่องนี้
- **ให้ Apps Script รันในนามผู้ใช้แต่ละคน** ไม่เลือก เพราะผู้ใช้ทุกคนต้องได้สิทธิ์เข้าไฟล์ Sheet โดยตรง ซึ่งทำลายการจำกัดการมองเห็นตามหน่วยงาน
