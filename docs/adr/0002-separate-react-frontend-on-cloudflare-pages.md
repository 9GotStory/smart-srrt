# ADR-0002: หน้าเว็บ React แยก วางบน Cloudflare Pages

* สถานะ: Accepted (PO อนุมัติผ่านการ Merge ของ PR #276)
* วันที่: 2026-11-16

## บริบท

ระบบเก่าให้ Apps Script ส่งหน้าเว็บเอง หน้าเว็บจึงอยู่ในกรอบ (iframe) ของ Google ซึ่งมีผลสามอย่าง

- การล็อกอินด้วย Google ทำตรง ๆ ไม่ได้ เอกสารทางการของ Apps Script ระบุว่า Web App ที่รันในนามเจ้าของจะไม่ได้อีเมลของผู้ใช้
- งานแต่ละงานไม่มีลิงก์ของตัวเอง จึงใส่ลิงก์ในข้อความ LINE ให้เปิดตรงไปที่งานไม่ได้
- หน้าจอบนมือถือติดกรอบของ Apps Script

โปรเจกต์ `epi-coverage` ของ PO ใช้หน้าเว็บ React ที่วางแยกบน Cloudflare Pages และใช้ Apps Script เป็น API PO รายงานว่าการล็อกอินด้วย Google ใช้งานได้ที่นั่น

## การตัดสินใจ

1. หน้าเว็บเป็นเว็บไซต์แยก เขียนด้วย React, TypeScript และ Vite อยู่ในโฟลเดอร์ `frontend/`
2. วางหน้าเว็บบน Cloudflare Pages
3. Apps Script ทำหน้าที่เป็น API อย่างเดียว อยู่ในโฟลเดอร์ `backend/` รับคำขอแบบ POST ที่ระบุ `action` และตอบเป็น JSON
4. หน้าเว็บที่วางไว้มีแต่โค้ดหน้าจอ ข้อมูลทั้งหมดมาจาก API หลังตรวจสิทธิ์

## ผลที่ตามมา

- ทุกงานและทุกเหตุการณ์มีลิงก์ของตัวเอง
- API เป็นที่อยู่ที่เรียกได้จากภายนอก ทุก action ยกเว้นการล็อกอินและตัวเลขรวมสาธารณะต้องตรวจ session ที่ server ก่อนอ่านข้อมูล
- Apps Script มองไม่เห็น IP และ header ของคำขอ จึงจำกัดการเรียกถี่ ๆ เป็นราย IP ไม่ได้ และตรวจไม่ได้ว่าคำขอมาจากหน้าเว็บของเราหรือไม่ การป้องกันทั้งหมดจึงอยู่ที่การตรวจ session token PO ยอมรับความเสี่ยงนี้เมื่อ 16 พฤศจิกายน 2026
- API รันในนามเจ้าของบัญชีคนเดียว ทั้งระบบจึงรับคำขอพร้อมกันได้จำกัดตามโควตาของ Apps Script ([`../schema.md` ข้อ 7](../schema.md#7-ขนาดที่ออกแบบรองรับ))
- Apps Script ตั้ง cookie ให้หน้าเว็บที่อยู่คนละที่ไม่ได้ session token จึงอยู่ในที่เก็บของเบราว์เซอร์ ซึ่งสคริปต์ในหน้าอ่านได้ หน้าเว็บจึงต้องจำกัดแหล่งของสคริปต์
- มีบริการที่ต้องตั้งค่าเพิ่มหนึ่งแห่ง PO เป็นผู้เชื่อม repository กับบัญชี Cloudflare
- repository นี้เป็นสาธารณะ ที่อยู่ของ API, OAuth client ID และ ID อื่นทั้งหมดอยู่ในค่าตั้งของ Cloudflare Pages และ Script Properties ไม่อยู่ในโค้ด
- สองโปรเจกต์ของ PO ใช้แนวทางเดียวกัน

## ทางเลือกที่ไม่เลือก

- **ให้ Apps Script ส่งหน้าเว็บเองต่อไป** ไม่เลือก ด้วยเหตุผลสามข้อในบริบท
- **GitHub Pages** ใช้ได้เพราะ repository เป็นสาธารณะ ไม่เลือก เพราะ PO มี Cloudflare Pages ที่ใช้กับ `epi-coverage` อยู่แล้ว
- **วางตัวกลางบน Cloudflare หน้า API** เพื่อจำกัดการเรียกถี่ ๆ และซ่อนที่อยู่ของ Apps Script ไม่ทำในรุ่นแรก เพราะเพิ่มส่วนที่ต้องดูแลอีกหนึ่งส่วน รูปแบบคำขอของ API ออกแบบให้เพิ่มตัวกลางนี้ภายหลังได้โดยไม่แก้หน้าเว็บ
- **Vanilla JavaScript ไม่มีขั้นตอน build** ไม่เลือก เพราะระบบใหม่มีหลายหน้าจอที่มีสถานะซับซ้อน และ PO มีโปรเจกต์ React ที่ใช้เป็นแบบได้
