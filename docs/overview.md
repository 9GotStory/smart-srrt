# Smart SRRT v2 — สรุปว่าเรากำลังจะสร้างอะไร

> สถานะ: เขียนเมื่อ 17 พฤศจิกายน 2026 หลังลงรายละเอียดฟีเจอร์ครบทั้ง 11 ข้อ ยังไม่มีโค้ดของ v2 เอกสารนี้อธิบายระบบที่**จะสร้าง**
> เอกสารนี้เป็นสรุปสำหรับคนที่ไม่ได้ร่วมออกแบบ ข้อ 1–9 เขียนสำหรับทุกคนใน สสอ. ข้อ 10–12 เขียนสำหรับ Product Owner (PO) รายละเอียดและแหล่งอ้างอิงอยู่ใน [`spec.md`](spec.md) เมื่อสองไฟล์เขียนไม่ตรงกัน spec เป็นแหล่งอ้างอิง และเมื่อ spec เปลี่ยนในเรื่องที่เอกสารนี้กล่าวถึง เอกสารนี้ถูกแก้ใน PR เดียวกัน

## 1. ระบบนี้คืออะไร

Smart SRRT คือทะเบียนรับแจ้งข่าวและเครื่องมือติดตามงานควบคุมโรคของสำนักงานสาธารณสุขอำเภอ (สสอ.) หนึ่งแห่ง ใช้ตั้งแต่ได้รับแจ้งว่ามีโรคหรือภัยสุขภาพในหมู่บ้าน ตรวจสอบข่าว มอบหมายงานให้หน่วยบริการลงพื้นที่ รับผลกลับ ติดตาม จนปิดเหตุการณ์

ระบบตอบคำถามสามข้อที่ตอนนี้ต้องไล่อ่านในแชต LINE

1. วันนี้ สสอ. ต้องทำอะไรกับเหตุการณ์ใดบ้าง
2. งานที่ส่งให้หน่วยบริการ ใครรับแล้ว ใครทำแล้ว งานใดเกินกำหนด
3. ทั้งปีมีเหตุการณ์กี่เรื่อง ผู้ป่วยกี่ราย และทำได้ทันเวลาตามมาตรฐานเท่าไร

ระบบนี้**ไม่ใช่**ระบบเวชระเบียน ไม่ใช่เครื่องมือวินิจฉัย และไม่ใช่ช่องทางแจ้งโรคตามกฎหมาย การรายงานผู้ป่วยผ่านระบบของกรมควบคุมโรคยังทำตามเดิม

## 2. ใครใช้ และทำอะไรได้

| ผู้ใช้ | คือใคร | ทำอะไรได้ |
|---|---|---|
| ผู้ดูแล | เจ้าหน้าที่ สสอ. อย่างน้อย 2 คน | ทุกอย่าง: รับแจ้ง ตรวจสอบข่าว ประเมินเกณฑ์ มอบหมายงาน รับผล ปิดเหตุการณ์ และจัดการผู้ใช้กับค่าตั้ง |
| ผู้ใช้หน่วยบริการ | เจ้าหน้าที่ของ รพ.สต. รพ. หรือ สสช. | แจ้งเหตุการณ์ รับงานของหน่วยตน บันทึกผล และแนบรูป เห็นเฉพาะเรื่องที่หน่วยของตนแจ้งหรือได้รับมอบหมาย |
| ผู้ดู | บุคลากรของ สสอ. ที่ไม่ได้บันทึกข้อมูล เช่น สาธารณสุขอำเภอ | เห็นทุกอย่างเท่าผู้ดูแล แก้ไขไม่ได้ |
| บุคคลทั่วไป | ไม่ต้องล็อกอิน | เห็นเฉพาะ Dashboard สาธารณะ ซึ่งเป็นจำนวนรวมรายตำบล |

ทุกคนเข้าระบบด้วยบัญชี Google ส่วนตัวของตนเอง ระบบไม่มีรหัสผ่านและไม่มีหน้าสมัครเอง ผู้ดูแลเป็นผู้เพิ่มอีเมลของผู้ที่เข้าได้

## 3. เหตุการณ์หนึ่งเรื่องเดินอย่างไร

เหตุการณ์หนึ่งเรื่องคือโรคหนึ่งโรคในหมู่บ้านหนึ่งแห่ง มีผู้ป่วยได้หลายราย และมีงานได้หลายงาน

```
รับแจ้ง → ตรวจสอบข่าว → ประเมินเกณฑ์ → มอบหมายงาน → รับผล → ติดตาม → ปิดเหตุการณ์
```

ตัวอย่าง: โรงพยาบาลแจ้งว่ามีผู้ป่วยไข้เลือดออกหนึ่งรายในหมู่ 5

1. **รับแจ้ง** ผู้ดูแลหรือหน่วยบริการบันทึกโรค หมู่บ้าน และรายละเอียด ระบบออกเลขที่เหตุการณ์ เช่น 2569-0012
2. **ตรวจสอบข่าว** ผู้ดูแลบันทึกว่าข่าวจริงหรือไม่ และตรวจสอบกับใคร
3. **ประเมินเกณฑ์** ผู้ดูแลบันทึกว่าเข้าเกณฑ์สอบสวนโรคหรือไม่ ระบบแสดงเกณฑ์ของโรคนั้นให้อ่าน และตั้งกำหนดเริ่มสอบสวนให้
4. **เพิ่มผู้ป่วย** ชื่อ อายุ เพศ บ้านเลขที่ หมู่บ้าน วันเริ่มป่วย การวินิจฉัย และสถานที่รักษา
5. **มอบหมายงาน** ระบบเสนอหน่วยบริการที่รับผิดชอบหมู่บ้านนั้นให้เอง สำหรับไข้เลือดออก ระบบเสนองานครบทุกรอบของมาตรการ 3-3-1 พร้อมกำหนดเสร็จ (ข้อ 6)
6. **แจ้งหน่วยบริการทาง LINE** ระบบเตรียมข้อความพร้อมลิงก์ ผู้ดูแลกดส่งในแชตของเจ้าหน้าที่หน่วยนั้น (ข้อ 5)
7. **หน่วยบริการทำงาน** เปิดลิงก์บนมือถือ รับงาน ลงพื้นที่ แล้วบันทึกเวลาที่ทำจริง ผล และรูปถ่ายไม่เกิน 6 รูป
8. **รับผล** ผู้ดูแลตรวจผลที่บันทึกมา ระบบบอกว่างานใดทันกำหนด และผลถึงเป้าของมาตรการหรือไม่
9. **ปิดเหตุการณ์** ผู้ดูแลบันทึกสรุปแล้วปิด ระบบไม่ปิดเอง และเปิดใหม่ได้เมื่อระบุเหตุผล

ทุกขั้นเป็นปุ่มที่กดได้ และทุกการกระทำถูกบันทึกในไทม์ไลน์ของเหตุการณ์ พร้อมชื่อผู้ทำ เวลาที่ทำจริง และเวลาที่บันทึก ข้อมูลไม่ถูกลบ รายการที่ผิดถูกยกเลิกพร้อมเหตุผล

## 4. หน้าจอของแต่ละคน

**ผู้ดูแล**

- **งานวันนี้** หน้าแรก แสดงสิ่งที่ต้องทำเป็นกลุ่ม เช่น รอตรวจสอบ รอประเมินเกณฑ์ ยังไม่ได้มอบหมายงาน งานเกินกำหนด ผลรอตรวจ และรอปิด แต่ละแถวมีปุ่มเดียวสำหรับขั้นถัดไป เหตุการณ์ของโรคติดต่ออันตรายและเหตุการณ์ที่มีผู้เสียชีวิตขึ้นก่อน
- **รายการเหตุการณ์** ทะเบียนของเหตุการณ์ทั้งหมด กรองได้ และค้นด้วยเลขที่เหตุการณ์
- **หน้าเหตุการณ์** ข้อมูล ผู้ป่วย งาน ผล รูปถ่าย และไทม์ไลน์ของเรื่องนั้น
- **สรุปภาพรวม** ตัวเลขของช่วงเวลาที่เลือก และการส่งออกเป็น Excel (ข้อ 7)
- **ตั้งค่า** ผู้ใช้ หน่วยบริการ หมู่บ้าน ประชากร รายการโรค และชุดโรค

**หน่วยบริการ** มีหน้าเดียวคือ **งานของหน่วย** ซึ่งทำสำหรับมือถือ มีงานที่ต้องทำเรียงตามกำหนดเสร็จ งานที่บันทึกผลแล้ว เหตุการณ์ที่หน่วยแจ้ง และปุ่ม "แจ้งเหตุการณ์"

**ผู้ดู** เริ่มที่หน้าสรุปภาพรวม เปิดงานวันนี้ รายการเหตุการณ์ และหน้าเหตุการณ์ได้ทุกเรื่อง โดยไม่มีปุ่มบันทึก

หน้าจอเป็นภาษาไทยทั้งหมด และมีคู่มือหนึ่งหน้าในเว็บสำหรับหน่วยบริการ กับอีกหนึ่งหน้าสำหรับผู้ดูแล

## 5. LINE

สสอ. กับหน่วยบริการยังประสานกันทาง LINE เหมือนเดิม สิ่งที่เปลี่ยนคือไม่ต้องพิมพ์ข้อความเอง

- ระบบเตรียมข้อความให้ ผู้ใช้กด "คัดลอก" หรือ "เปิด LINE" แล้วเลือกผู้รับและส่งเอง ระบบไม่ส่งข้อความเองในรุ่นแรก
- ข้อความมีหกชนิด: ผู้ดูแลแจ้งงานใหม่ ติดตามงาน และแจ้งยกเลิกงาน หน่วยบริการแจ้งเหตุการณ์ แจ้งผู้ป่วยรายใหม่ และแจ้งว่าบันทึกผลแล้ว
- ข้อความบอกเลขที่เหตุการณ์ โรค หมู่บ้าน งาน และกำหนดเสร็จ **ไม่มีชื่อผู้ป่วยและบ้านเลขที่** ผู้รับกดลิงก์แล้วล็อกอินจึงเห็นรายละเอียด
- ลิงก์เปิดในเบราว์เซอร์ของเครื่อง เช่น Chrome หรือ Safari เพราะการล็อกอินด้วย Google ใช้ไม่ได้ในเบราว์เซอร์ที่อยู่ในแอป LINE

## 6. ไข้เลือดออกและโรคที่นำโดยยุงลาย

รุ่นแรกมี "ชุดโรค" หนึ่งชุด ใช้กับไข้เด็งกี่ ไข้ปวดข้อยุงลาย และโรคติดเชื้อไวรัสซิกา ทำตามมาตรการ 3-3-1 (3-7-14-21-28) ของกรมควบคุมโรค ฉบับ พ.ศ. 2569

| รอบ | งาน | กำหนดเสร็จ |
|---|---|---|
| วันที่ 0 | ลงพื้นที่บ้านผู้ป่วย | 3 ชั่วโมงหลังได้รับรายงาน |
| วันที่ 1 | สำรวจ ทำลายแหล่งเพาะพันธุ์ และพ่นสารเคมี รัศมี 100 เมตร | 24 ชั่วโมงหลังได้รับรายงาน |
| วันที่ 3 | พ่นสารเคมีซ้ำ | สิ้นวันที่ 3 |
| วันที่ 7 | สำรวจซ้ำ รัศมี 100 เมตร พร้อมค่า HI และ CI | สิ้นวันที่ 7 |
| วันที่ 14 | สำรวจทั้งหมู่บ้าน พร้อมค่า HI | สิ้นวันที่ 14 |
| วันที่ 21 | สำรวจทั้งหมู่บ้านและสถานที่ พร้อมค่า HI และ CI | สิ้นวันที่ 21 |

- ผู้ป่วยรายแรกของเหตุการณ์ได้งานทั้งหกรอบ ระบบเสนอให้ผู้ดูแลยืนยันในแบบเดียว และคำนวณกำหนดเสร็จให้
- ระบบเทียบผลกับเป้าสองด้าน: ทำทันเวลาหรือไม่ และค่า HI กับ CI ถึงเป้าของรอบนั้นหรือไม่
- หน้าเหตุการณ์บอกว่าวันนี้เป็นวันที่เท่าไรของระยะเฝ้าระวัง 28 วัน และเหตุการณ์ขึ้นกลุ่ม "รอปิด" เมื่อครบ 28 วันโดยไม่มีผู้ป่วยรายใหม่
- โรคอื่นใช้ขั้นตอนทั่วไปในข้อ 3 การเพิ่มชุดโรคของโรคอื่นทำได้ในรุ่นถัดไปโดยไม่ต้องแก้โครงสร้างข้อมูล

## 7. ตัวเลขและการส่งออก

- **สรุปภาพรวม** จำนวนเหตุการณ์ ผู้ป่วย และผู้เสียชีวิต แยกตามโรค เดือน และพื้นที่ อัตราป่วยต่อประชากรแสนคน ผลงานของแต่ละหน่วยบริการ ตัวชี้วัดที่ 6, 8 และ 10 ของมาตรฐานทีมระดับอำเภอ พ.ศ. 2563 และร้อยละที่ถึงเป้าของมาตรการ 3-3-1 รายสัปดาห์ระบาด
- **ส่งออก Excel สามไฟล์** ตัวเลขสรุป ข้อมูลเต็มของเหตุการณ์ ผู้ป่วย และงาน และแบบติดตามมาตรการ 3-3-1 ไฟล์ไม่มีชื่อและบ้านเลขที่ เว้นแต่ผู้ดูแลเลือกให้รวม
- **Dashboard สาธารณะ** หน้าที่ประชาชนเปิดได้โดยไม่ล็อกอิน แสดงจำนวนเหตุการณ์และผู้ป่วยรายตำบล รายเดือน ปรับปรุงทุกวันจันทร์ จำนวน 1 ถึง 4 แสดงเป็น "<5" เพื่อไม่ให้คนในพื้นที่เดาตัวผู้ป่วยได้ โรคติดต่ออันตรายและโรคที่มีการตีตราไม่แสดงชื่อ และผู้ดูแลเปิดปิดหน้านี้ได้เอง

## 8. ข้อมูลผู้ป่วยและความปลอดภัย

- ระบบเก็บชื่อ อายุ เพศ บ้านเลขที่ หมู่บ้าน วันเริ่มป่วย การวินิจฉัย และสถานที่รักษา **ไม่เก็บเลขบัตรประชาชนและ HN**
- ชื่อและบ้านเลขที่เห็นได้เฉพาะบุคลากรของ สสอ. และหน่วยบริการที่มีงานผูกกับผู้ป่วยรายนั้นหรือเป็นผู้เพิ่มผู้ป่วยรายนั้น หน่วยบริการอื่นเปิดลิงก์เดียวกันแล้วได้คำตอบว่าไม่พบ
- รับเฉพาะรูปถ่ายของงานในพื้นที่ ห้ามถ่ายใบหน้าผู้ป่วยและเอกสารที่มีชื่อ
- ข้อมูลอยู่ใน Google Sheets และ Google Drive ของบัญชีเจ้าของระบบ ระบบสำรองฐานข้อมูลเองทุกสัปดาห์ และบุคลากร สสอ. อีกคนหนึ่งถือบัญชีสำรองที่เก็บสำเนาไว้แยกกัน
- ชื่อ บ้านเลขที่ และรูปถ่ายเก็บ 10 ปีนับจากวันปิดเหตุการณ์ ข้อมูลอื่นเก็บตลอดอายุของระบบ
- ต้องมีอินเทอร์เน็ต รุ่นแรกยังบันทึกแบบออฟไลน์ไม่ได้

## 9. รุ่นแรกมีอะไร และยังไม่มีอะไร

**มี:** ทุกอย่างในข้อ 2–8

**ยังไม่มี เลื่อนไปรุ่นถัดไป**

- ร่างรายงานสอบสวนโรคด้วย AI
- ส่งข้อความ LINE อัตโนมัติ และอีเมลสรุปงานค้างทุกเช้า
- ชุดโรคของโรคอื่น และหน้าจอให้ผู้ดูแลสร้างแบบบันทึกเอง
- การใช้งานแบบออฟไลน์
- ประชากรแยกอายุ

**ไม่ทำ:** หน้าสมัครสมาชิกเอง การแนบไฟล์เอกสาร การเชื่อมกับ D506 หรือระบบรายงานของกระทรวง และองค์กรปกครองส่วนท้องถิ่นไม่มีบัญชีในระบบ หน่วยบริการเป็นผู้ประสานและบันทึกผลแทน

## 10. ลำดับการสร้าง

แต่ละช่วงจบด้วยระบบที่ลองใช้ได้จริง ทุกช่วงใช้ข้อมูลสมมติจนถึงการอนุมัติในช่วงที่ 6 รายละเอียดอยู่ใน [`roadmap.md`](roadmap.md) ยังไม่มีกำหนดวันของแต่ละช่วง

| ช่วง | สิ่งที่ลองใช้ได้เมื่อจบ |
|---|---|
| 0 วางโครง | หน้าเว็บเปล่ากับ API ที่ตอบได้บนที่อยู่จริง ระบบเก่าหยุดให้บริการ |
| 1 | ล็อกอินด้วย Google จัดการผู้ใช้ หน่วยบริการ หมู่บ้าน ประชากร และรายการโรค |
| 2 | ผู้ดูแลเดินเหตุการณ์จากรับแจ้งถึงปิด มีงานวันนี้และรายการเหตุการณ์ |
| 3 | มอบหมายงาน ข้อความ LINE และหน่วยบริการทำงานจนจบบนมือถือ |
| 4 | ชุดโรคติดต่อนำโดยยุงลายตามมาตรการ 3-3-1 |
| 5 | ผู้ดู สรุปภาพรวม ส่งออก Excel และ Dashboard สาธารณะ |
| 6 | สำรองข้อมูล คู่มือ หน่วยบริการ 2 แห่งทดลองใช้ แล้วเริ่มใช้ข้อมูลจริง |

## 12. สำหรับ PO: การตัดสินใจหลัก ความเสี่ยงที่ยอมรับ และเรื่องที่ยังไม่ยืนยัน

**การตัดสินใจหลัก** เหตุผลอยู่ใน [`adr/`](adr/README.md)

- สร้างใหม่ทั้งหมดบน Google Apps Script และ Google Sheets เดิม หน้าเว็บ React แยกอยู่บน Cloudflare Pages ไม่มีค่าใช้จ่ายและไม่มีเซิร์ฟเวอร์ให้ดูแล
- เข้าสู่ระบบด้วย Google และตรวจอีเมลกับตารางผู้ใช้ บทบาทมี 3 แบบ และ server เป็นผู้ตัดสินสิทธิ์ทุกคำขอ
- โครงสร้างข้อมูลแกนกลางตายตัว ขั้นตอนเฉพาะโรคเป็นชุดโรคที่เพิ่มได้โดยไม่แก้ตาราง
- ระบบเตรียมข้อความ LINE ผู้ใช้ส่งเอง
- หลังเริ่มใช้ข้อมูลจริงมีสองชุดที่แยกกัน Claude Code ทำงานในชุดทดสอบเท่านั้น และทุก Deploy ขึ้นชุดใช้งานจริงต้องให้ PO สั่ง merge เข้า `release`

**ความเสี่ยงที่ PO ยอมรับแล้ว**

- ข้อมูลสุขภาพอยู่ในบัญชี Gmail ส่วนตัว ถ้าเจ้าของบัญชีย้ายงาน ต้องสร้างชุดใหม่ในบัญชีใหม่แล้วกู้คืนข้อมูล
- การกู้คืนจากชุดสำรองเสียข้อมูลได้ถึง 7 วัน และเมื่อบัญชีเจ้าของถูกลบ รูปถ่ายหาย
- Dashboard สาธารณะแสดงครบทุกตำบล รวมสองตำบลที่ประชากรต่ำกว่า 5,000 คน
- หน่วยบริการกรอกค่า HI และ CI ซ้ำกับแอปสมาร์ท อสม. ไปก่อน และทบทวนหลังการทดลองใช้
- ทั้งระบบพึ่งบริการของ Google และรับคำขอพร้อมกันได้จำกัด

**เรื่องที่ยังไม่ยืนยัน (Not Verified)** รายการเต็มอยู่ใน [`spec.md` ข้อ 11](spec.md#11-ข้อเสนอที่รอ-po-ยืนยัน)

- ลิงก์จากแชต LINE เปิดในเบราว์เซอร์ของเครื่องและล็อกอินได้บนมือถือจริง พิสูจน์ในช่วงที่ 1 ถ้าไม่ผ่าน ต้องหยุดและเลือกวิธีล็อกอินใหม่
- หน้าจอพร้อมใช้ภายใน 3 วินาทีบนมือถือ เป็นเป้า ยังไม่ใช่ผลที่วัดแล้ว วัดในช่วงที่ 0
- การเผยแพร่จำนวนรวมรายตำบลอยู่ในขอบเขตของมาตรา 10 ของพระราชบัญญัติโรคติดต่อ พ.ศ. 2558 หรือไม่ Dashboard สาธารณะของชุดใช้งานจริงปิดอยู่จนกว่าได้คำตอบ
- ผู้ควบคุมข้อมูลส่วนบุคคลของงาน สสอ. คือหน่วยงานใด ต้องแจ้งผู้ป่วยหรือไม่ และระยะเวลาเก็บ 10 ปีถูกต้องตามระเบียบหรือไม่
- มีกฎที่ห้ามเก็บข้อมูลผู้ป่วยในบัญชีส่วนบุคคลหรือไม่ การค้นยังอ่านเอกสารสองฉบับที่เกี่ยวข้องไม่ได้
